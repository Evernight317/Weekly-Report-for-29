## 一、项目概览

`agents-go` 的目标是做一个**可对话的 Agent 智能体助手**：用户注册登录后，在网页上与 Agent 多轮对话，由后端执行「思考—行动—观察」（ReAct）循环并返回结果。

当前形态是**标准的「Go 后端 API + React 单页前端」前后端分离架构**：

```
┌────────────────────────────┐         HTTP / JSON          ┌──────────────────────────┐
│   浏览器 (React 18 SPA)     │  ─────────────────────────▶  │        Go 后端            │
│   Vite 5 / axios / Router  │  ◀─────────────────────────  │  Gin + ent + JWT + Agent  │
└────────────────────────────┘                              └────────────┬─────────────┘
                                                                         │ pgx
                                                                         ▼
                                                                  PostgreSQL 16
```

- 前端只负责**界面渲染、交互与登录态**，不直接接触数据库；
- 后端用 `Authorization: Bearer <JWT>` 校验身份，`/api` 分组统一挂鉴权中间件；
- 全部接口以 `doc/API.md` 为契约，文档中用 ✅ / 🚧 标注实现状态。

**一句话总结当前进度**：**「用户体系 + 工程底座」已经闭环，「Agent 本体」还是空的。**
骨架搭得很完整，但项目名字里的那个 Agent，目前连一个能跑通的接口都还没有。

## 二、技术选型与特点

### 2.1 后端选型

| 层次 | 选型 | 版本 | 选型理由与特点 |
| :--- | :--- | :--- | :--- |
| 语言 | **Go** | `1.26.6` | 编译型、并发友好、单二进制部署，适合长耗时的 Agent 请求 |
| Web 框架 | **Gin** | `v1.12.0` | 路由分组 + 中间件链天然适配「公开路由 / 鉴权路由」的划分 |
| ORM | **ent** | `v0.14.6` | schema-as-code，**图结构（edge）** 表达关系，代码生成保证类型安全 |
| 数据库 | **PostgreSQL** | `16-alpine` | 关系型 + JSON 文本字段，兼顾结构化用户数据与对话历史 |
| 驱动 | **pgx/v5** | `v5.10.0` | 经 `database/sql` 接入，再用 `entsql.OpenDB` 桥接给 ent |
| 认证 | **golang-jwt/v5** | `v5.3.1` | HS256 对称签名，签发/校验逻辑集中在一个 Service |
| 口令 | **bcrypt** | `x/crypto v0.49.0` | 加盐哈希存储，`Sensitive()` 标记防止哈希值进日志 |
| 配置 | **viper** | `v1.21.0` | 支持多格式，本地与容器用两份 yaml 区分 |
| 主键 | **google/uuid** | `v1.6.0` | `DefaultFunc(uuid.NewString)`，DB 层自动生成，不依赖自增 |
| 部署 | **Docker 多阶段 + scratch** | — | 编译产物直塞空镜像，体积最小、攻击面最小 |

**后端架构特点**：

1. **分层清晰**：`cmd/api`（进程入口）→ `internal/auth`（业务：注册/登录/鉴权）→ `ent`（数据层）→ `configs`（配置）。业务代码不碰 HTTP 细节之外的东西。
2. **中间件式鉴权**：`protected := r.Group("/api"); protected.Use(auth.AuthMiddleware(authSvc))`。以后新增受保护接口，只要挂进这个分组就自动受保护，不会漏配。
3. **schema-as-code + 自动迁移**：`ent/schema/` 里用 Go 结构体描述表，启动时 `client.Schema.Create(ctx)` 自动建表。开发期很爽（改字段即生效），但**生产环境属于隐患**。
4. **关系已建模但未启用**：`User` 有 `edge.To("sessions", Session.Type)`，`Session` 有反向 `edge.From(...).Field("user_id").Required()`，外键关系在 ORM 层已经连通，只差 handler。
5. **对话存储用 Text 存 JSON**：`Session.messages` 是 `field.Text`，即把整段对话历史序列化成 JSON 塞进一个字段。实现简单，但**无法按消息查询、无法分页、并发写入会互相覆盖**。

### 2.2 前端选型

| 层次 | 选型 | 版本 | 选型理由与特点 |
| :--- | :--- | :--- | :--- |
| 框架 | **React** | `18.3.1` | 生态成熟、组件化清晰，适合聊天这类状态驱动界面 |
| 构建 | **Vite** | `5.4.11` | 冷启动与热更新快，内置 dev 代理与环境变量机制，联调方便 |
| 路由 | **react-router-dom** | `6.28.0` | 声明式路由，配合守卫组件实现「未登录跳登录页」 |
| 请求 | **axios** | `1.7.9` | 拦截器机制统一处理 JWT 附加与 401 自动下线 |
| 全局状态 | **Context API** | — | 登录态是「全局只读 + 少数动作」，Context 够用且零额外依赖（不引入 Redux） |
| 样式 | **原生 CSS** | — | 单文件 `index.css`（538 行），无 UI 库依赖 |
| 持久化 | **localStorage** | — | 存 `agents_token` / `agents_user`，刷新不丢登录态 |

**前端架构特点**：

1. **四层分明**：`api/`（网络层）→ `context/`（全局状态）→ `components/`（复用组件）→ `pages/`（页面）。
2. **状态管理粒度克制**：登录态放 Context（全局），聊天消息留在 `Chat` 页面的局部 `useState`。不为了「统一」把页面级状态也塞进全局，这是很务实的取舍。
3. **双拦截器兜住登录态**：请求拦截器自动补 `Bearer`，响应拦截器统一捕获 `401` 清态跳登录，业务代码里没有一处重复的错误处理。
4. **长耗时做了体验设计**：Agent 请求超时放宽到 **180 秒**，等待期用「思考中」文案 + 打字动画反馈，避免界面假死。
5. **开发期用 Vite 代理绕开跨域**，生产期用 `VITE_API_BASE_URL` 直连。

## 一、HTTP 协议

**定义**：超文本传输协议，规定了服务器和浏览器之间数据传输的规则。

**特点**：
1. 基于 TCP 协议
2. 基于请求-响应模型
3. 无状态协议（无法共享两次请求的信息）

### 1. 请求协议

| 请求方式 | 组成 |
|---------|------|
| GET | 请求行 + 请求头 |
| POST | 请求行 + 请求头 + 请求体 |

- **请求行** = 请求类型 + 资源路径 + HTTP 协议版本
- **请求头** = 状态码、User-Agent 等
- **请求体** = POST 请求的参数

### 2. 响应协议

- **响应行** = 协议 + 状态码 + 描述
- **响应头**：
  - `Content-Type`：响应内容格式
  - `Content-Length`：响应内容长度
  - `Cache-Control`：缓存控制
- **响应体** = 响应数据

### 3. 状态码

| 范围 | 含义 | 示例 |
|------|------|------|
| 1XX | 临时响应状态码 | WebSocket 升级 |
| 2XX | 成功处理 | 200 OK |
| 3XX | 重定向 | 301、302 |
| 4XX | 客户端问题 | 404 Not Found |
| 5XX | 服务端问题（bug） | 500 Internal Server Error |

参考：https://cloud.tencent.com/developer/chapter/13553

## 二、Web 服务器

**定义**：封装了 HTTP 协议操作，简化 Web 程序开发，部署 Web 项目，对外提供网上信息浏览服务。

### Tomcat

- 一个轻量级服务器
- 支持 Servlet、JSP 等少量 JavaEE 规范
- 也被称为 **Web 容器** 和 **Servlet 容器**

### Servlet 与 Tomcat 的关系

| 概念 | 性质 | 说明 |
|------|------|------|
| Servlet | Java 技术规范（概念） | 定义了 Java Web 组件的标准 |
| Tomcat | Servlet 容器（具体软件） | 实现了 Servlet 规范，让 Servlet 能跑起来 |

## 三、架构模式

| 架构 | 组成 | 特点 |
|------|------|------|
| BS 架构 | Browser + Server | 浏览器访问，无需安装客户端 |
| CS 架构 | Client + Server | 需要安装客户端，性能更好 |

## 四、完整请求响应模型

```text
用户操作
   ↓
浏览器生成 HTTP 请求
   ↓
DNS 解析 → 获取 IP
   ↓
TCP 三次握手（+ TLS 握手）
   ↓
发送 HTTP 请求 → 服务器
   ↓
服务器处理（路由、业务逻辑、数据库）
   ↓
返回 HTTP 响应
   ↓
浏览器解析、渲染、执行 JS
   ↓
页面呈现给用户
```

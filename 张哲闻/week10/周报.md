## 一、本周学习概览

这周集中看 AI Agent，接着上周 RAG 之后的内容往下走：

- **四种主流分类**：聊天机器人基于上传内容生成提示词，自动拆分、分配任务；规划智能体负责把原始需求拆解，落地成带节点、执行人的具体任务；反思评估智能体用正负反馈评估输出、迭代优化模型能力，本质上内置了强化学习；多智能体系统是多个角色分工协作，目前已经能独立完成商业级软件开发。
- **核心结构**：能力底座是大模型，决定 Agent 的能力上限和推理能力；底座之上是四大核心模块——规划、动作执行、工具调用、记忆。
- **规划模块**：和规划智能体呼应，把大目标拆成可执行的子任务序列，拆得好不好直接影响后面每一步。
- **工具调用与动作执行**：让模型不止能"说"，还能"做"——调 API、查知识库、操作外部系统。上周看的 RAG 在这里就成了 Agent 手里的一个工具。
- **记忆模块**：大模型的上下文窗口有限，记忆模块负责把历史对话和中间结果存下来，任务越长越离不开它。
- **主流范式 ReAct**：推理（Reason）和行动（Act）交替进行——模型先想一步，调一次工具，拿着返回的观察结果再想下一步，循环往复直到任务完成，构成智能体的完整运行闭环。

## 二、遇到的问题与解决

**问题**：一开始把"聊天机器人"和 Agent 画等号，看了四种分类反而糊涂了：能对话的就算 Agent 吗？

**解决**：区分点不在"能不能对话"，而在有没有"规划—执行—反馈"的闭环。聊天机器人按这个分类只是 Agent 里最简单的一种，而多智能体、规划智能体已经能自主拆任务、调工具、检查结果，复杂度完全不在一个量级。

**问题**：ReAct 这个词看了好几遍才反应过来是 Reason + Act 的缩写，一开始还以为和前端的 React 框架有什么关系。

**解决**：把"想一步—做一步—看结果—再想"的循环画成图之后发现，它其实就是四大模块串起来跑的样子：规划负责想，工具调用和动作执行负责做，记忆把前面的过程留着。画完图再看各种 Agent 产品的行为就都能对上了。

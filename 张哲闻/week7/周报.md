## 一、本周学习概览

这周看博客模块，是几个模块里表最多的，文章、评论、点赞、标签一堆表：

- **发布与编辑**：草稿和已发布是同一个表用 status 字段区分，发布前会做归一化处理；第一次发布会触发粉丝广播。
- **列表与详情**：可见性判断（公开 / 仅自己）直接下沉到 SQL 条件里，而不是查回来再用 Java 过滤；浏览量是数据库原子自增，防止并发下丢计数。
- **点赞**：blog_like 表上 UNIQUE(post_id, user_id)，靠唯一索引天然幂等，重复点赞插不进去，比先查再插省一次交互。评论点赞同理。
- **评论**：楼中楼结构花了最多时间——root_id 指向楼主评论，parent_id 指向被回复的那条，两层引用就能搭出"评论区里的回复区"。评论被回复还会触发消息通知。
- **标签**：存在文章表的一个 JSON 字段里，配一张标签字典表，没搞中间表多对多。

## 二、遇到的问题与解决

**问题**：楼中楼的 root_id 和 parent_id 一开始分不清各自管什么，看 SQL 都看不懂在查什么。

**解决**：自己画了张图——一条评论既是某个楼的 root，又可能是别人的 parent。列表查询是先按 root_id 把楼捞出来，楼下的回复再按 parent_id 挂上去。画完图再回去看代码就通了。

**问题**：疑惑为什么点赞不先查一下"点没点过"再操作。

**解决**：先查再插在高并发下会两个人同时通过检查，唯一索引从存储层把这个问题兜住了，这个思路比应用层判断更可靠。

## 一、本周学习概览

这周看认证模块，核心是登录态的"怎么来、怎么验、怎么失效"。比上周顺利一些，因为用户模块已经把分层结构趟熟了：

- **JWT**：登录成功后签发 token，payload 里放了 userId、role 这些信息。之前只知道 JWT 是无状态的，这周才认真去看了签名校验的过程。
- **authState 机制**：这是这周觉得最巧的设计。token 里存一个由 id、权限、状态、密码哈希四要素算出来的 HMAC-SHA256 摘要，每次校验时拿数据库当前值重算一遍比对——改密码、封号、调角色，旧 token 立刻作废，不用维护黑名单也不用加版本列。代价是每次校验多一次单行查询，算是拿查询换"即时失效"。
- **滑动续期**：通过 X-Refresh-Token 头下发新 token，但有个 30 天的硬上限（Redis 记首次签发时间），不是无限续。
- **权限控制**：URL 规则、方法级注解、Service 里兜底判断，一共三层。
- **邮箱验证码**：验证码用 SET EX 存 Redis，校验完就删（一次性），发送有按场景的限频。

## 二、遇到的问题与解决

**问题**：想不通既然 JWT 是无状态的，为什么项目里每个请求还要查一次数据库。

**解决**：纯粹的无状态 token 没法主动作废——密码泄露了，旧 token 在过期前一直有效。authState 每次查库重算就是为了让"改密码"能立刻踢掉所有旧登录态。无状态和即时失效本来就矛盾，这个方案是折中。

**问题**：JWT 相关的依赖和工具类一坨，几个类翻来翻去晕了。

**解决**：按"签发 → 放进响应头 → 网关/过滤器解析 → 校验"的顺序把链路画在纸上，再对着代码走一遍就清楚了。

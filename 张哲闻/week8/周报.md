## 一、本周学习概览

这周收尾看通用模块。它不承载具体业务，是给其他模块打底的，反而把前几周攒的不少疑问解释掉了：

- **统一返回与异常**：Result + ErrorCode + BizException 的组合，Service 里只管 throw，GlobalExceptionHandler 统一翻译成带错误码的响应，controller 里看不到一堆 try-catch。
- **操作日志**：operation_log 表和业务操作放同一个事务落库，要么都成功要么都回滚；operator_user_id 设计成删用户后置空显示"系统"，外键用的是 SET NULL 而不是 CASCADE。
- **验证码基础设施**：上周认证模块里看的发送限频、一次性消费，底层实现在这里。EmailCodeStore 有 Redis 和内存两个实现，Redis 挂了能降级。
- **统一缓存**：cache-aside 的公共封装，上周用户模块里那个 `__NULL__` 哨兵和延迟双删都是从这里下发的，等于把上上周挖的坑填上了。
- **请求横切**：MDC 做链路追踪（日志里能串起一次请求）、防重复提交、QPS 按秒分桶统计，全是过滤器 / 拦截器层面的事。

## 二、遇到的问题与解决

**问题**：业务表操作要记日志，为什么日志表和业务放同一个事务？平时都说日志写失败不该影响主流程。

**解决**：这里是审计日志不是运行日志，追求的是"记录的操作和实际发生的操作严格一致"，分开写会出现业务回滚了但日志说成功的情况。两种日志目标不同，不能套同一个结论。

**问题**：MDC 一直没搞明白是什么。

**解决**：就是个线程级别的 Map，请求进来时往里面塞个 traceId，日志输出格式里带上这个字段，同一个请求的所有日志就能串起来查。自己改 logback 配置试了一下就明白了。

# 高级OOP

## 一、static关键字

### 1.变量

| static                                                                                                      | 无                                                 |
| ----------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| **类变量** ，被整个类共享，只有一份                                                                  | **实例变量**（对象变量） ，每个对象都有一个 |
| 使用时，通过类名访问，且同一类访问可以不加类名<br />`Student.age = "李华";`<br />同样，类变量是在堆区存储 |                                                    |

```Java
public class Student {
	static String name = "博士";
  	int age;
}
```

所有对象的名字都是博士，相当于每个对象都是博士的不同年龄（切片）

#### 应用

某个数据只需要一份，且希望能够被共享访问、修改，则可定义成类变量。如系统启动后，要求用户类可以记住自己创建了多少个用户对象。

---

### 2.方法

| static             | 无       |
| ------------------ | -------- |
| 类方法（静态方法） | 对象方法 |
| 基本与变量相同     |          |

#### 应用

工具类，用于给开发人员实现特定功能；同时，实例方法需要单独创建一个对象，且该对象仅用于调用方法，内存开销大，采用工具类就不需要创建对象了；不过，工具类构造器一般要求 **私有化** ，防止创建对象，浪费内存。

例如，对于一个系统，注册和登录账号需要不同位数的验证码，可以抽象成工具类，减小码量

实体类不能设计成类方法！因为实体类是涉及到具体的对象的（没法像C++一样引用，即使作为形参也要拷贝，内存开销很大

### 3.main方法

有 `static` ，所以是类方法；运行的时候，JVM会自动调用类方法 `Test.main()` ；至于main的形参 `String[] args` 是一个String数组，运行前是可以传参给String数组（虽然没什么用。

### 4.注意事项

- 类方法中可以直接访问类的成员，不可直接访问实例成员；
- 实例方法中可以直接访问类成员，也可以直接访问实例成员；
- 实例方法中可以出现this关键字，类方法中不可出现this关键字

### 5.代码块

|      | 静态代码块                                                           | 实例代码块                                                             |
| ---- | -------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 格式 | `static {}`                                                        | `{}`                                                                 |
| 特点 | 类加载时自动执行；由于类只会加载一次，所以静态代码块也只会执行一次。 | 每次创建对象时，执行实例代码块，并**在构造器前** 执行。         |
| 作用 | 完成类的初始化；如对类变量的初始化赋值。                             | 和构造器一样，都是用来完成对象的初始化的，如对实例变量进行初始化赋值。 |
| 应用 |                                                                      | 对象创建日志可以通过实例代码块实现                                     |

### 6.单例设计模式

#### 设计模式

| 设计模式 |                                      |
| -------- | ------------------------------------ |
| 概念     | 软件开发中，对于某个特定问题的最优解 |
| 内容     | 1、解决什么问题<br />2、怎么写       |

#### 单例设计模式

| 单例设计模式       |                                                                                |
| ------------------ | ------------------------------------------------------------------------------ |
| 目的               | 确保某个类只有一个对象                                                         |
| 应用               | Runtime类、win的任务管理器（只能启动一个）                                     |
| 常见的单例设计思路 | 饿汉式单例：调用对象时，对象已创建；<br />懒汉式单例：调用对象时，才创建对象； |

#### 饿汉式单例

1、把类的构造器私有。
2、定义一个类变量记住类的一个对象
3、定义一个类方法，返回对象。

对于类变量也是唯一实例 `a` ，由于其位于类内部，所以可以调用被修饰为 `private` 的无参构造器，而在类外，无参构造器则无法被调用；如果写成 `public A get_Object ()` 即实例方法，那么调用则需要创建对象，由于私有无参构造器无法实现，导致无法获得这个唯一实例

```Java
public class A  {
    private static A a = new A(); // 私有静态实例

    private A (){ // 私有无参构造器

    }
    public static A get_ObjectA () { // 静态方法返回唯一实例
        return a;
    }
}
```

#### 懒汉式单例

1、把类的构造器私有
2、定义一个类变量用于存储对象。
3、 提供一个类方法，保证返回的是同一个对象。

如果单例被频繁使用，选择饿汉式提前创建对象；否则选择懒汉式即可，随用随建；

## 二、继承

### 1.继承

`extends 类名`

称为父类/子类或基类/派生类；

子类拥有父类的所有实例成员，但是子类只能 **直接** 访问父类的 **非私有** 成员，无法访问父类的私有成员。若要访问，需通过父类的非私有成员方法访问，如 `get/set` 等；（可以认为父类的私有成员是父类特有的，不能直接用）

```Java
public class Fu {
	private int a;
  	public int b;
}

public class Zi extends Fu {
	// 该类中有变量a和b
  	public void Print () {
      	// 报错，子类无法直接访问父类的私有成员
    	// System.out.println (a);
      	System.out.println (b);
    }
}
```

子类的创建由 **父类子类共同** 完成，具体表现为：创建子类对象时，在方法区中 **同时加载** 父类和子类，同时根据父类和子类决定子类所有成员；同时，当在子类中调用继承自父类的方法时，是去 **父类字节码** 中找到对应的方法并执行；

继承作用：减小码量，提高复用性；

### 2.继承注意事项

#### ①权限修饰符

| 修饰符           | 本类 | 同一包的其他类 | 任意包的子类 | 任意包的任意类 |
| ---------------- | :--: | :------------: | :----------: | :------------: |
| `private`      |  √  |                |              |                |
| 缺省（无修饰符） |  √  |       √       |              |                |
| `protected`    |  √  |       √       |      √      |                |
| `public`       |  √  |       √       |      √      |       √       |

#### ②单继承

java中的类只支持 **单继承** ，即子类只能有一个父类（即没有菱形继承），但是可以有 **多层继承** ，即爷爷->父亲->儿子这种；

#### ③Object类

java中，`Object` 类是所有类的祖宗，即所有类直接或间接成为 `Object` 的子类。

当创建一个类时，如果其没有父类，那么默认父类是 `Object` 类。从而，所有类都可以调用 `Object` 类中的一些方法

#### ④方法重写

在子类中，可以通过方法重写覆盖父类的方法，要求 **方法名、形参列表** 均与父类对应方法一致。

在方法重写后，java在访问方法时会遵循 **就近原则** 。

方法重写时，可以在子类方法上方 **加上  `@override` 注释** ，加上后可以指定编译器检查方法重写的正确性，同时也能指出子类对应的方法是方法重写，提高可读性；

方法重写时，子类方法访问权限必须 **大于等于** 父类该方法的权限，即 `public>protected>缺省` ；

私有方法、静态方法不能被重写；

重写的方法返回值类型，范围上必须 **小于等于** 被重写方法的返回值；

##### 方法重写常见应用

重写Object类的 `toString ()` 方法，以返回对象的内容。 `toString ()` 方法默认是返回对象的地址，与直接输出对象名作用一致。

而对于 `ArrayList` ，其直接输出对象名可以输出集合内容，就是重写了 `toString ()` 方法；

#### ⑤子类访问成员的原则

核心就是 **就近原则** ，或者说注意成员的作用域（变量、方法大体一致），优先级为 **局部>子类>父类** ；

以 `name` 为例，想要访问特定的成员的话，需要用如下关键字：

|   局部   | 访问子类中的 |  访问父类中的  |
| :------: | :-----------: | :------------: |
| `name` | `this.name` | `super.name` |

`this` 就是代表当前对象的关键字，而 `super` 则可以指定访问父类的成员变量/方法；

对于变量需要考虑局部变量的问题，而对于方法则只有子类中的和父类中的，因此父类只需要一个 `super` 关键字即可。

#### ⑥子类构造器

子类创建对象时，先调用父类构造器，再执行子类构造器。并且一般情况下默认调用的是父类的 **无参** 构造器；

原因：由于继承规则，子类中的成员变量相当于被拆分到多个类中（不一定都能被子类初始化）。因此，在构造子类时，必须从父类开始，逐个调用多个构造器，才能将子类的所有成员变量全部初始化；

对于子类的所有构造器，都会在第一行默认加上 `super ()` ，即调用父类的 **无参** 构造器；如果父类没有无参构造器（单有参）就会报错，这时要在子类构造器第一行手动加上 `super (...)` ，即调用父类的 **有参** 构造器。

```Java
class A {
	public A () {
    	System.out.println ("父类无参构造器")；
    }
  	public A (int age) {
      	System.out.println ("父类有参构造器");
    }
}
class B extends A {
	public B () {
      	// 编译器自动加上
    	// super ();
  
        // 如果将父类无参构造器注释，此时就会报错
      	// 解决方法就是手动加上形参，即调用有参构造器
      	super (18);
      	System.out.println ("子类无参构造器");
    }
  	public B (String name, int age) {
    	// 编译器自动加上，而且默认父类无参构造器
      	// super ();
  		System.out.println ("子类有参构造器");
    }
}
```

##### this和super的一些使用技巧

可以通过`this (...)` 的方式调用该类的 **其他构造器**（有参构造器又不是只有一个，对吧）

例如，对于下面这个类，要求学校没填的话默认是东北大学（即C++ 中的函数默认参数，但java不支持默认参数），可以通过如下方式实现。

注意点

- `this ()` 和 `super` 一样 也必须写在构造器 **首行** ！当子类使用 `this`时，对应的有参构造器第一行默认为`super`，只有`this`位于第一行才能确保先执行`super` ，即先对父类成员初始化；
- `this` 和 `super` 不可同时出现！如上点， `this` 执行时可能已经执行了 `super` ，此时再执行 `super` 相当于执行两遍；

```Java
class Student{
	private String name;
  	private int age;
  	private String school;

  	public Student (){
  
    }
  	public Student (String name, int age, String school) {
      	this.name = name;
      	this.age = age;
      	this.school = school;
    }
  	public Student (String name, int age) {
      	// 这种写法和上面的有参构造器重复了
      	// this.name = name;
      	// this.age = age;
      	// this.school = "东北大学";

      	// 通过this (...)可大幅简化
      	this (name,age,"东北大学");
    }
}
```

## 三、多态

### 1.介绍

多态表现：对象多态、行为多态；

多态与继承/实现有关（java注重行为多态？

对象多态：people作为人对象，既可以指向学生，又可以指向老师；

行为多态：同样是人对象，执行run方法有多种可能，比如跑得快慢；

行为多态判断： *编译看左边，运行看右边* 。对于下面的 `p1.run ()` 以及其上一行 `People p1 = new Student ()` ，编译（写代码）时，编译器检查的是左边`people` 类中有没有 `run` 方法（写代码时，将其视为`people` 类进行编译检查）；而在实际运行时，则调用的是右边实际对象类型中的  `run` 方法，即学生类的`run`方法；

（父类指向子类对象，并面向父类对象code）

```Java
People p1 = new Student(); // 此处学生范围小于人，即小范围赋给大范围，自动转换
p1.run();
People p2 = new Teacher();
p2.run();
```

多态前提：有 **继承/实现** 关系；存在 **父类引用子类** 对象；存在 **方法重写** ；

### 2.特点

紧耦合/解耦合：前者可以认为是各个模块紧密相连，牵一发动全身；后者则是各个模块相对独立，修改一个不会对其他模块造成影响；

- 多态可以实现解耦合，右边对象可以随时切换，后续业务随机改变。比如，对于`People p1 = new Student ()` ，后面跟有相关代码，当想将该模块切换对象为Teacher时，只需要修改第一行即可；
- 定义方法时，可以使用父类类型的形参，以此接收一切子类对象，扩展性更强、更便利。如 `public static void go(People p)` ，父类类型作为形参可以同时接受学生和老师两种对象类型；
- 多态下不能使用子类的 **独有功能** 。根据运行多态原则：编译看左边，由于子类独有功能不会写在父类中，因此编译检查时就会报错；（也可以这么理解，由于是父类用子类，但是编译看左边，即编译判断时还是当成父类处理，因此不会存有子类独有的方法），解决这个需要使用 *多态类型转换* ；

### 3.多态类型转换？？？

#### 类型转换

自动类型转换、强制类型转换

#### 多态类型转换

为了使用子类的独有功能，可以进行强制类型转换，即通过把对象转换成真实的类型，从而调用子类的独有方法。。

只要有继承/实现关系，就可以进行强制类型转换，且此时不会报错；

但运行时，如果发现对象的 *真实类型* 与 *强转后类型* 不同，则会报错 **类型转换异常**（ClassCastException）

```Java
People p1 = new Student ();
Student s1 = (Student) p1;
p1.test (); // 此时可以调用学生类的特有功能

// 这样写能通过编译，但是运行阶段会报错
// 编译阶段，由于只看左边即认为p1是人，和老师存在继承关系，所以不报错
// 但运行阶段看右边，此时p1真实类型是学生而不是老师，与强转类型不符无法互相指向，故报错
Teacher t1 = (Teacher) p1;
```

因此，在强制转换前，可以加关键字 `instanceof` 用来 *判断当前对象的真实类型* ，从而使转换类型正确。

格式为 `对象 instanceof 类型`，若一致则返回 `true`

比如，当使用父类形参接受子类时，在强制转换前可以用`instanceof` 先判断类型再转换。

```Java
if (p instanceof Teacher) {
  	Teacher t1 = (Teacher) p;
  	t1.run ();
}
else if (p instanceof Student) {
  	Student s1 = (Student) p;
  	s1.run ();
}
```

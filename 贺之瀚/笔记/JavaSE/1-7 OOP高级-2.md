# OOP高级-2

## 一、final

`final` 可以修饰变量、方法、类，并且对应不同作用；

|      | 变量                                                                     | 方法                                                 | 类                                                |
| ---- | ------------------------------------------------------------------------ | ---------------------------------------------------- | ------------------------------------------------- |
| 作用 | 该变量只能被赋值一次<br />（必须初始化，初始化完之后<br />值不再改变？） | 被称为*最终方法* ；<br />不能被 **重写** ； | 被称为*最终类* ；<br />不能被 **继承** ； |

常量：被final修饰的静态成员变量 ；建议

修饰类：该类被称为最终类，特点是不能被继承了。
修饰方法：该方法被称为最终方法，特点是不能被重写
修饰变量：该变量只能被赋值一次。

### 1.final修饰变量

这里的`final` 作用上和 `const` 非常像了

*变量分类*：局部变量、成员变量（此处的成员变量作用类似于全局变量）；成员变量又可以分为静态成员变量和实例成员变量（static）；

- `final` 修饰局部变量时，就是只能被赋值一次；
- `final` 修饰静态成员变量时，该变量只有初始化时会被赋值，随后不会再改变。这时候也可以称之为 **常量** ，即被 `public static final`  修饰的静态成员变量。对于常量， *命名规则* 为：名称全部大写，多个单词下划线连接 ；
- `final` 一般不会修饰实例成员变量，这样会使所有对象的该变量固定，意义不大；

注意点

- final修饰基本类型的变量，变量存储的 **数据** 不能被改变。
- final修饰引用类型的变量，变量存储的 **地址** 不能被改变，但地址所指向对象的 **内容** 是可以被改变的。

本质上，无论那种都是变量储存的数据不变（引用因为存的是堆上地址）

### 2.常量

被 `static final`  修饰的成员变量；

通常用于记录系统的配置信息；

#### 执行原理

程序编译后，常量会被 **宏替换** ：出现常量的地方全部会被替换成其记住的字面量；这样可以保证使用常量和直接用字面量的性能是一样的。

## 二、抽象类

关键字：`abstract` ，可以修饰类和方法；

对于抽象类：

1. 抽象类 **不能创建对象** ，仅作为一种特殊的父类，让子类继承并实现；
2. 一个类继承抽象类，必须 **重写** 完抽象类的 **全部抽象方法** ，否则这个类也必须定义成抽象类；
3. 类有的成员（成员变量、方法、构造器）抽象类都具备。

对于抽象方法：

- 抽象方法只有 **方法签名** ，不能写方法体；

两者关系：

抽象类中可以不写抽象方法，但有抽象方法的类一定是抽象类。

一个应用：父类知道每个子类都要做某个行为，但每个子类要做的情况不一样，父类就定义成抽象方法，交给子类去重写实现，我们抽出这样的抽象类，就是为了更好的支持多态。如：需要管理猫、狗的数据。猫的数据有：名字，行为是：喵喵喵的叫；狗的数据有：名字，行为是：汪汪汪的叫。可以设计抽象类，把 `cry` 方法设计成抽象方法；

### 2.模版设计模式

模版方法可以将代码重复部分抽出来简化；

#### 模板方法设计模式的写法

1. 定义一个抽象类。
2. 在里面定义2个方法。一个是模板方法：放入相同代码；一个是抽象方法：具体实现交给子类完成。

如，老师和学生都有相同部分，但根据身份一句话不同，可以设计成下面模式；

**执行原理** ：当执行 `t.write ()` 时，由于继承父类，因此去调用父类中的对应字节码，到了 `writeMain ()` 方法时，则会优先执行子类中重写的方法；

- 模版方法一般建议加上 `final` 关键字，以防止被子类重写失去模板作用；

```Java
public abstract class People {
    public void write () {
        System.out.println("111");
        System.out.println(writeMain());
        System.out.println("333");
    }
    public abstract String writeMain ();
}

// main方法
Teacher t = new Teacher ();
t.write ();
```

## 三、接口

关键字： `interface`，格式如下

```Java
public interface 接口名｛
	//成员变量（常量）
	//成员方法（抽象方法）
}
```

- 接口中，只允许有 **成员变量和成员方法** 两种成员，且成员变量一定是 **常量** ，成员方法一定是 **抽象方法** ，即默认加上对应的修饰符；（因此接口可以视为特殊的抽象类？）
- 接口无法被实例化（无法创建对象）；
- 接口是用来被 类 **实现(implements)** 的，实现接口的类被称为 **实现类** ，格式如下

```Java
修饰符 class 实现类名 implements 接口1,接口2,接口3... {
  
}
```

- 一个类可以实现 **多个** 接口（可以理解成特殊的继承）；实现多个接口时，必须重写完 **全部接口的全部方法** ，否则需定义成抽象类；

#### 接口应用

- 弥补了单继承的局限，使一个类可以实现 **多种** 功能。java中只允许单继承，但实际中，一个对象可能有多种属性，此时就可以利用接口及运行多态 实现对象的多重属性；
- 相比直接在类中添加对应方法更加清晰简明；
- 面向接口编程。一个接口可以被多个类实现，而接口在使用时也是 **多态** 的体现，即接口调用实现类，并且面向接口进行coding，对于某个特定接口及对应业务，可以 *通过切换实现类达到按需切换业务* 的目的；

#### 接口新增特性-三种方法

| 默认方法                                     | 私有方法                | 静态方法               |
| -------------------------------------------- | ----------------------- | ---------------------- |
| 必须有关键字`default` ，<br />属于实例方法 | 必须有关键字`private` | 必须有关键字`static` |
| 默认被`public` 修饰                        |                         | 默认被`public` 修饰  |

- 三种方法都可以拥有 **方法体**  ；

作用：当某个抽象函数需要修改时，可以直接创建一个还有方法体的新方法，然后其余实现类直接调用新方法，无需对每个实体类的方法都修改；

#### 接口多继承

和类的继承不同，接口可以同时继承多个接口；

作用：当某个实现类需要实现多个接口时，可以创建一个继承这些接口的接口，实现继承接口就相当于实现了所有接口；

```Java
// 定义
public interface C extends B,A{ 
}

public interface A { 
}
public interface B {
}
// public class C implements A,B {
// }
// 更简单的写法
public interface C extends A,B {
}
public class D implements C { 
}
```

#### 接口注意点

1、继承多个接口时，如果多个接口中存在 **方法签名冲突** ，则此时不支持多维承。（方法名相同，但返回值类型不同）

实现时，无法全部实现抽象方法；

2、实现多个接口时，如果多个接口中存在 **方法签名冲突** ，则此时不支持多实现。

实现时，无法全部实现抽象方法；

3、一个类继承了父类，又同时实现了接口，父类中和接口中有 **同名的默认方法** ，实现类会优先用 **父类** 的。

4、一个类实现了多个接口，多个接口中存在同名的默认方法，此时会冲突，但是在实现类中 **重写** 该方法即可解决；

# RAG

RAG核心：创建一个AI可以调用的向量数据库，使得LLM在回答问题时根据该数据库作答，从而提高准确率、降低幻觉产生的可能性，同时还能标注回答依据来源，使得回答更加真实可靠；

## 一、Index 索引构建

将各种来源的数据标准化处理后切分成多个语义完整独立的小块，并把这些分块的内容向量化后存入数据库；

### 1.数据获取&预处理

### 2.分块

原则：每个分块包含完整的语义单元

| 分块方式     |              |
| ------------ | ------------ |
| 句子分块     | 可能切断语义 |
| 固定大小分块 |              |

#### 参数

块大小：一般是150-400字，对应200-500tokens；

重叠：一般10-20%块大小，防止关键信息被截断（也能帮助理解该块的语义？）；

### 3.向量化*

文字->数字向量；

向量化解决的主要是搜索匹配的问题。仅靠关键词的方式，有时候无法做到语义的匹配；比如退订和取消续费

向量化可以认为是将语义编码为向量，而对相似的定义则是通过夹角余弦判断的，越接近于1则相似度越高；

## 二、Retrieval 检索

### 向量检索

将用户问题预处理后转化成向量，在向量数据库中寻找高相似度分块；

### 实际检索策略

向量（语义）+关键词，两者综合后选取前三个；

## 三、Generate 生成

文档+预处理后问题，经过提示词工程后交给LLM生成结果；

后处理：给出回答依据，审查并格式化内容；

## 四、查询优化

能够使回答更加精确完整；

### 1.多查询策略

一个问题可以被多个角度描述，而这些问题的答案一直；

因此可以让LLM根据原问题生成多个语义近似问题，多个问题并行查询数据库，对得到结果去重排序，生成最终结果；

其实就是多角度提问或者说多问几次取交集，提高准确率？

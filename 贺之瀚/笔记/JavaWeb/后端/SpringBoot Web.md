## 二、HTTP协议

超文本传输协议，规定了浏览器和服务器之间数据传输的规则（即格式）；

三大特点：

1. 基于TCP协议： 面向连接，安全
2. 基于请求-响应模型的：一次请求对应一次响应
3. HTTP协议是**无状态** 的协议：对于事务处理没有记忆能力。每次请求-响应都是独立的；优点：速度快；缺点：多次请求间不能共享数据；

### 1.请求协议&请求数据格式

#### 请求行

请求数据第一行：请求方式、资源路径、协议；

#### 请求头

第二行开始，格式key：value即一堆键值对；

|                 |                          |
| --------------- | ------------------------ |
| host            | 请求主机名               |
| User-Agent      | 浏览器版本               |
| Accept          | 浏览器能接受的资源类型   |
| Accept-Language | 浏览器偏好语言           |
| Accept-Encoding | 表示浏览器支持的压缩类型 |
| Content-Type    | 请求主体数据类型         |
| Content-Length  | 请求主体大小（字节）     |

#### 请求体

通过一个**空行** 和请求头隔开；

POST请求特有（大小没有限制），存放请求参数；

### 2.响应协议&响应数据格式

#### 响应行

响应数据第一行（协议以及协议版本、状态码、描述）；

状态码表示请求成功还是失败，描述就是对状态码的英文描述；

| 状态码 |                                                                                               |
| :----: | --------------------------------------------------------------------------------------------- |
|  1xx  | 响应中-临时状态码，表示请求已经接收，告诉客户端应该继续请求或者如果它已经完成则忽略它         |
|  2xx  | 成功-表示请求已经被成功接收，处理已完成                                                       |
|  3xx  | 重定向-重定向到其他地方；让客户端再发起一次请求以完成整个处理                                 |
|  4xx  | 客户端错误-处理发生错误，责任在客户端<br />如：请求了不存在的资源、客户端未被授权、禁止访问等 |
|  5xx  | 服务器错误-处理发生错误，责任在服务端<br />如：程序抛出异常等                                 |

重定向：（浏览器自动完成）资源的位置发生移动，服务端会返回新的资源地址，浏览器接受后访问新的地址获取资源；

| 状态码 | 对应状态                                 |
| :----: | ---------------------------------------- |
|  200  | 请求成功                                 |
|  404  | Not Found，请求资源不存在                |
|  500  | 服务器端发生不可预期的错误，多为抛出异常 |

#### 响应头

第二行开始的，同样是key:value形式的键值对

|                  |                                                                |
| ---------------- | -------------------------------------------------------------- |
| Content-Type     | 表示该响应内容的类型<br />例如text/html，application/json      |
| Content-Length   | 表示该响应内容的长度<br />（字节）                             |
| Content-Encoding | 表示该响应压缩算法<br />例如gzip                               |
| Cache-Control    | 指示客户端应如何缓存<br />例如max-age=300表示可以最多缓存300秒 |
| Set-Cookie       | 告诉浏览器为当前页面所在的域设置cookie                         |

#### 响应体

同样通过空行和响应头隔开；

最后一部分，存放响应数据

### 3.协议解析

客户端解析/服务端解析

客户端解析由浏览器完成，服务端可以用轮子-Web服务器，本质是一个程序，对HTTP协议的操作进行了封装，使得不用直接对协议操作；

## 三、Web服务器-Tomcat

### 介绍

Web服务器是一个软件程序，对HTTP协议的操作进行封装，从而简化了web开发；Web服务器可以部署Web项目，主要功能是**提供网上信息浏览服务** ；

Tomcat[官网地址](https://tomcat.apache.org/) ；是一个轻量级的web服务器，支持servlet、jsp等少量javaEE规范，也被称为web容器、servlet容器。

### 使用

修改终端字符集编码：`conf/logging.properties` 中找到 `java.util.logging.ConsoleHandler.encoding`（51行），修改成GBK即可；

端口号配置：`conf/server.xml`找到 `<Connector port = "8080"` 修改即可；注意，*HTTP协议默认端口号为80* ，如如果将Tomcat端口号改为80，则将来访问Tomcat时，将不用输入端口号；

#### 启动&停止Tomcat

启动：`bin/startup.bat`

1. `Ctrl+C`
2. `bin/shutdown.bat`
3. 直接关闭cmd窗口

### 项目部署

将项目放置到webapps目录下，即部署完成；

## 四、SpringBootWeb-入门程序解析

springboot创建项目时需要联网；

### 起步依赖

利用maven的依赖传递特性，将常用的基础依赖合在了一起，即引入一个依赖就相当于引入了所有的常用依赖；

SpringBoot父工程中统一管理了版本号version；

### 内嵌Tomcat服务器

基于SpringBoot开发的Web应用程序，内嵌了tomcat服务器（SpringBoot的依赖中包含了Tomcat），因此启动项目时也会默认 *启动内嵌Tomcat服务器* ，调用监听端口8080；

# Day7-Redis缓存

## 缓存菜品

> 用户端小程序展示的菜品数据都是通过查询数据库获得，如果用户端访问量比较大，数据库访问压力随之增大（**慢查询**）
> 通过Redis来缓存菜品数据，可以减少数据库查询操作

具体步骤：查询前多一步判断是否存在缓存，有就读取，没有就查询后缓存；

- key可以是菜品分类对应的id，即每个分类下菜品保存一份缓存（查询的时候是展示所有菜品，所以这里所有菜品存成**一个value**就行）；
- 

Redis中key的命名规则：`dish_#{菜品分类id}`

Controller中的过程：

1. 构造key
2. 查询Redis中有没有菜品数据
3. 有的话就读Redis缓存
4. 没有的话就调用Service Mapper查询**并缓存**；

数据库修改时，已有的对应缓存要清除（增删改、起售停售）；

管理端清除缓存；

- 删除时，可能涉及多个分类，方便点的操作是全部删除；
- 修改也是，可以涉及多个分类；
- 起售停售
- 无论哪种，清除缓存可以*抽象成一个单独的成员方法*；

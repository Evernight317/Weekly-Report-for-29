`java` 中的面向对象和 `C++` 差不多，不过在具体使用中，对象由于属于引用类型，因此 `java` 强制要求动态分配，也就是先分配再使用。

---

## 一、执行原理&内存模型

|    方法区    | 栈上               | 堆区                                                                                                              |
| :----------: | ------------------ | :---------------------------------------------------------------------------------------------------------------- |
| 类的实现代码 | 对象在堆区中的地址 | 对象的具体数据，还存储<br /> **对象对应的类在方法区的地址** ，<br />只要是同一个类产生的对象，这个地址相同 |

## 二、注意事项

类中，成员变量的一般都有默认值，遵循每种变量的规则，因此一般情况下不对成员变量赋值；

一个包中，只能有一个类被 `public` 修饰，且这个类的 **类名必须和文件名一致** ；

多个变量指向同一对象时，会相互影响（这是由 `java` 对于引用类型数据的内存分配模型引起的）；

```Java
s1.name = "张三"；
System.out.println(s1.name); // 张三
Student s2 = s1; // s1中存储的学生对象的地址赋给了s2变量！
s2.name = "李四";
System.out.println(s1.name); // 李四
```

如果某个对象没有一个变量引用它，则该对象无法被操作，会成为所谓的垃圾对象，或者说该对象不可达。此时， `java` 的内存管理器会自动释放该对象的内存。

## 三、this

`C++` 中，`this` 是一个指针常量；而在 `java` 中，`this` 则是一个 **变量** ，在类的方法中使用时，可以认为存储的是当前变量地址，即可以获得当前对象，主要用来解决方法中同名变量的冲突问题。

`java` 中，`this` 必须 **显式** 给出！

```Java
public void Compare (int score) {
// 冲突，均会优先调用形参的score
	// if (score > score)
 //    	System.out.println ("yes");
	if (this.score > score)
		System.out.println ("yes");
}
```

## 四、构造器

其实就是 `C++` 中的构造函数

构造器必须 **与类同名 ，且没有返回值** 。分为无参数构造器和有参数构造器；创建对象时，会自动调用构造器；构造器能够实现对对象成员变量的自动初始化赋值；若未给出构造器，则 `java` 会自动生成一个无参构造器，若已有有参构造器，则 **不会自动生成无参构造器** ，需手动给出；

```Java
// 调用无参数构造器
Student s = new Student ();
// 调用有参数构造器
Student s = new Student ("大宝界徐盛"，90)；
```

## 五、封装

和 `C++` 差不多，通过关键字 `public` `private` 实现；对于方法，如果要与外界交互的话就是 `public` ；

## 六、实体类

成员变量均为 `private` ，且仅对外提供相应的 `set` `get` 方法，除此外没有其他方法；类中必须有一个公共的无参构造器；实体类的作用就是保存数据。实际应用中，实体类仅负责数据存取，而其他类负责数据的处理；

实体类主要还是一种思想，把数据的存储和处理放在不同的类中，仅提供对应的 `set` `get` 方法维护数据

### 本质

在实际处理时，数据的存储和处理是分开的两个类。因此，负责处理的类需要新建一个实体类对象作为成员变量来接受数据，然后才能实现处理，相当于要复制一遍实体类。故实体类的思想本质上是空间换安全性（分开的话，相当于实际面对的就是一个具体对象而不是抽象对象，所以要有一个对象作为实体类对象的载体）

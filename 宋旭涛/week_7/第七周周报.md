## 二、核心学习内容

### 2.1 Nginx 反向代理与负载均衡
- **反向代理优势**：
  1. **提高访问速度**：Nginx 可起到缓存作用，加速静态资源访问。
  2. **负载均衡**：将客户端请求分发到多台服务器，减小单台服务器压力。
  3. **保证后端服务安全**：防止外界直接访问后端服务，避免服务器被攻击。
- **配置方式**：在 `nginx.conf` 中设置 `server` 属性，可设定监听端口、转发地址，自定义匹配请求规则与转发目标。
- **负载均衡**：通过声明一组服务器（`upstream`），由 Nginx 自主将请求平分到不同服务器地址。

### 2.2 Swagger 接口文档
- **核心功能**：按照 Swagger 规范定义接口及接口相关信息，自动生成接口文档及在线接口调试页面。
- **Knife4j 集成**：使用 Knife4j 相关配置，注册名为 `Docket` 的 Bean 对象由 Spring Boot 管理，需配置静态资源映射。
- **常用注解**：
  - `@Api`：用在类上（如 Controller），表示对类的说明。
  - `@ApiModel`：用在实体类、视图类上。
  - `@ApiModelProperty`：用在属性上。
  - `@ApiOperation`：用在方法上（如 Controller 方法）。

### 2.3 ThreadLocal 线程隔离
- **核心概念**：线程的局部变量，为每个线程提供单独一份存储空间，具有线程隔离效果，仅在线程内可获取对应值（客户端每次请求对应一个单独线程）。
- **应用场景**：在 Service 层通过 ThreadLocal 获取拦截器中解析的 JWT 令牌信息，识别当前操作用户身份。

### 2.4 Redis 数据库
- **核心特性**：基于内存的 Key-Value 结构数据库，读写性能极高，适合存储热点数据（热点商品、资讯、新闻），作为 MySQL 的补充。
- **安全配置**：默认无密码，可在配置文件中设置（仅需密码，无需账号）。
- **数据类型**：
  1. `string`：最基本的数据类型。
  2. `hash`：可存储对象。
  3. `list`：列表，支持左右插入数据。
  4. `set`：无序集合，无重复元素，支持集合运算。
  5. `sorted set`：有序集合，元素关联分数（`score`），按分数升序排序。
- **常用命令**：
  - **字符串**：`SET key value`、`GET key`、`SETEX key seconds value`、`SETNX key value`
  - **哈希**：`HSET key field value`、`HGET key field`、`HDEL key field`、`HKEYS key`、`HVALS key`
  - **列表**：`LPUSH key value`、`LRANGE key start stop`、`RPOP key`、`LLEN key`
  - **集合**：`SADD key member`、`SMEMBERS key`、`SCARD key`、`SINTER key1 [key2]`、`SUNION key1 [key2]`、`SREM key member`
  - **有序集合**：`ZADD key score member`、`ZRANGE key start stop [withscores]`、`ZINCRBY key increment member`、`ZREM key member`
  - **通用命令**：`KEYS pattern`、`EXISTS key`、`TYPE key`、`DEL key`
- **Java 操作**：使用 Spring Data Redis 客户端，创建模板配置类，创建五种不同类型的操作对象用于操作 Redis 数据库。

### 2.5 HttpClient
- **核心功能**：提供高效、功能丰富、支持 HTTP 协议的客户端编程工具包，支持 HTTP 协议最新版本。
- **使用步骤**：
  1. 创建 HttpClient 对象。
  2. 创建 Http 请求对象。
  3. 调用 HttpClient 的 `execute` 方法发送请求。

### 2.6 缓存设计与 Spring Cache
- **缓存思路**：通过 Redis 缓存数据减少数据库查询，在数据库与后端服务间加缓存层；每个分类下的菜品保存一份缓存数据，数据库变更时清理缓存保证一致性。
- **Spring Cache 框架**：基于注解的缓存抽象，底层可切换 Redis、Caffeine 等不同实现。
- **常用注解**：
  - `@EnableCaching`：开启缓存注解功能（加在启动类）。
  - `@Cacheable`：方法执行前查缓存，有则直接返回，无则调用方法并将返回值放入缓存。
  - `@CachePut`：将方法返回值放入缓存。
  - `@CacheEvict`：从缓存中删除一条或多条数据。
- **Key 生成规则**：与 `cacheNames` 相关，格式为 `cacheNames::key`；支持 SpEL 表达式动态取值（如 `key = "#user.id"`），也可取返回值属性（`"#result.id"`）。

## 四、问题与解决方案

| 问题 | 解决方案 |
| --- | --- |
| Nginx 反向代理配置后请求转发失败 | 检查 `nginx.conf` 中 `server` 的 `listen` 端口与 `proxy_pass` 地址是否正确，确保后端服务已启动 |
| Swagger 页面无法访问，静态资源 404 | 检查是否配置了静态资源映射，确认 `Docket` Bean 正确注册且扫描路径包含 Controller 包 |
| ThreadLocal 中存储的用户信息在线程复用场景下出现串号 | 在请求结束后（如拦截器 `afterCompletion`）调用 `remove()` 方法清理 ThreadLocal 数据 |
| Redis 缓存与数据库数据不一致 | 采用 Cache-Aside 模式，在数据库更新操作后通过 `@CacheEvict` 主动清理对应缓存 |
| Spring Cache 的 key 生成重复导致数据覆盖 | 使用 SpEL 表达式动态生成 key，如 `key = "#categoryId"` 确保不同分类数据独立缓存 |

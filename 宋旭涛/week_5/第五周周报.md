## 二、核心学习内容

### 2.1 RESTful 开发规范

使用资源复数命名 URL（如 `/departments`、`/employees`），通过 HTTP 动词表示操作：

- `GET` 查询
- `POST` 新增
- `PUT` 修改
- `DELETE` 删除

路径参数定位资源，查询参数用于过滤分页；统一返回 `{code, msg, data}` 响应格式。

### 2.2 日志记录（@Slf4j）

使用 Lombok 的 `@Slf4j` 注解生成 `log` 对象，通过 `log.info/debug/error` 记录关键信息。

配置多环境日志级别，开发用 `DEBUG`，生产用 `INFO`，便于调试与问题追踪。

### 2.3 Spring Boot 分层架构

- **Controller 层**：接收请求、校验参数、调用 Service 并返回响应。
- **Service 层**：处理业务逻辑（如部门存在性校验）、事务控制。
- **Mapper 层**：使用 MyBatis 操作数据库，支持动态 SQL。
- **统一异常处理**（`@ControllerAdvice`）：保证错误响应格式一致。

### 2.4 核心接口

- **部门管理**：查询、新增、修改、删除（级联处理关联员工）。
- **员工管理**：分页查询（支持多条件筛选）、新增、修改、删除。

## 四、问题与解决方案

| 问题 | 解决方案 |
| --- | --- |
| RESTful 路径设计不规范（含动词） | 统一改为资源复数 + HTTP 动词，如 `DELETE /departments/{id}` |
| 新增员工时未校验部门是否存在，导致外键异常 | Service 层增加部门校验，不存在则抛自定义异常 |
| 日志输出过多，生产环境可能泄露信息 | 配置 `spring.profiles` 区分环境，生产设为 `INFO` 级别 |
| 全量更新时前端漏传字段导致置 null | 约定前端传递完整对象，并添加 `@NotNull` 校验 |
| 删除部门时未处理下属员工 | 增加检查，若部门有员工则拒绝删除，避免数据不一致 |

# 学习笔记/记录
本周主要学习了 MyBatis 框架及其在 Spring Boot 环境下的应用，核心知识点如下：
## MyBatis 基础与配置：
- 了解了 MyBatis 作为持久层框架的核心作用，即简化 JDBC 开发，实现对象与数据库表的映射（ORM）。
- 掌握了在 Spring Boot 中引入 mybatis-spring-boot-starter依赖及配置数据库连接的方法。
- 学习了 Lombok​ 插件的使用，通过注解自动生成 Getter/Setter/Constructor，大幅提升实体类编写效率。
## 数据库连接池：
- 理解了连接池（如 Spring Boot 默认的 HikariCP）的作用：复用连接、避免频繁创建销毁带来的性能开销。
- 了解了 DataSource接口的核心方法 getConnection()。
## SQL 执行与防注入机制：
- 预编译 (#{})：使用 #{}进行参数占位，本质是 PreparedStatement。优势在于能有效防止 SQL 注入，且支持预编译缓存，提高执行效率。
- 字符串拼接 (${})：使用 ${}是直接拼接 SQL 字符串，存在注入风险，通常仅用于表名、排序字段等非用户输入场景。
## CRUD 操作与结果处理：
- 增删改查：掌握了基础的增删改查操作，以及插入操作如何通过 @Options(useGeneratedKeys=true)注解实现主键回填。
- 数据封装：解决了实体类属性名与数据库字段名不一致的问题，通过配置 map-underscore-to-camel-case开启驼峰命名自动映射。
动态 SQL (XML 映射)：
学习了使用 XML 文件编写复杂 SQL，并通过标签实现动态拼接：
- `<if>`：根据条件判断是否拼接 SQL 片段。
- `<where>`：智能生成 WHERE关键字，并自动剔除多余的 AND。
- `<set>`：用于更新操作，自动处理逗号分隔。
- `<foreach>`：用于遍历集合（如 IN查询），生成 (1,2,3)形式的 SQL。
- `<sql>`& `<include>`：抽取公共 SQL 片段，减少代码冗余。
# 遇到难题解决方法

## 难题：SQL 注入风险与模糊查询的冲突
- 困难描述：在实现模糊查询（LIKE）时，发现使用 #{}占位符无法直接拼接 %通配符，而使用 ${}虽然能拼接字符串，但存在严重的 SQL 注入风险。
- 解决方法：查阅资料后确认，正确的做法是继续使用安全的 #{}，但在 Java 代码或 XML 中通过字符串拼接函数处理通配符。即在传入参数前加上 %，或者在 XML 中使用 CONCAT('%', #{name}, '%')进行包裹，这样既保证了安全，又实现了模糊匹配功能。
## 难题：数据库字段与实体类属性映射失败
- 困难描述：查询数据时，发现部分字段（如 create_time）总是返回 null，尽管数据库中有值。
- 解决方法：检查发现实体类属性名为 createTime（驼峰命名），而数据库字段为 create_time（下划线命名）。MyBatis 默认不会自动转换这两种命名方式。通过在 application.yml中配置 mybatis.configuration.map-underscore-to-camel-case: true，开启了驼峰自动映射，成功解决了数据封装问题。

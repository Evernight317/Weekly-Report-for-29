## 二、核心学习内容

### 2.1 文件上传与云存储
- **接收文件**：使用 `MultipartFile` 类型接收前端文件，形参名需与表单项名一致。
- **存储方案**：
  1. **本地存储**：使用 `transferTo` 保存，为防止覆盖需结合 UUID 重命名。
  2. **云存储（OSS）**：使用对象存储服务，文件存入 Bucket，通过密钥鉴权。
- **配置管理**：利用 `@ConfigurationProperties` 注解结合 yml 配置文件管理 OSS 必备参数，实现自动注入。

### 2.2 登录校验与会话技术
- **会话跟踪**：掌握 Cookie、Session 及主流的 JWT（令牌）技术。
- **JWT 令牌**：由 Header（Base64编码）、Payload（自定义信息）、Signature（防篡改签名）组成；解析时密钥必须匹配，异常即代表令牌非法。
- **统一校验**：
  - **过滤器（Filter）**：JavaWeb 三大组件之一，通过 `doFilter` 方法实现通用拦截（如登录校验），需 `@ServletComponentScan` 开启支持。
  - **拦截器（Interceptor）**：运行在过滤器之后，可精确控制拦截/排除路径，且能直接注入为 Bean。
- **异常处理**：通过 `@ControllerAdvice` 全局异常处理器统一包装错误结果。

### 2.3 事务管理
- **声明式事务**：使用 `@Transactional` 注解将业务方法交给 Spring 管理，自动完成开启、提交与回滚。
- **回滚控制**：默认仅 RuntimeException 回滚，可通过 `rollbackFor` 属性指定异常类型。
- **传播行为**：通过 `propagation` 属性控制事务方法嵌套时的行为逻辑。

### 2.4 AOP 面向切面编程
- **核心思想**：基于动态代理，将日志记录、事务管理等“横切逻辑”与核心业务解耦。
- **核心概念**：连接点（JoinPoint）、通知（Advice）、切入点（Pointcut）、切面（Aspect）、目标对象。
- **通知类型**：`@Around`（前后）、`@Before`（前）、`@After`（后，类似 finally）、`@AfterReturning`（正常返回）、`@AfterThrowing`（异常）。
- **切入点表达式**：`execution`（按方法签名匹配）与 `@annotation`（按注解匹配），可通过 `@Pointcut` 抽取复用。
- **执行顺序**：同一切面按 Around->Before->目标->After 顺序；不同切面通过 `@Order` 控制优先级。

### 2.5 Spring Boot 原理剖析
- **配置优先级**：`properties` > `yml` > `yaml`。
- **Bean 管理**：默认单例（`singleton`），可通过 `@Scope` 改为多例（`prototype`）。
- **第三方 Bean**：无法使用 `@Component` 时，采用 `@Bean` 在配置类（`@Configuration`）中声明，方法名即为 Bean 名，支持形参自动装配。
- **自动配置原理**：基于 `@ComponentScan`（组件扫描）与 `@Import`（导入配置类），配合起步依赖（Maven 传递）实现“开箱即用”。

### 2.6 AI Agent 拓展知识
- **RAG 架构**：检索增强生成，通过外挂知识库解决大模型幻觉问题，流程涵盖文档加载、切片、向量化存储与检索生成。
- **Agent 原理**：智能体具备“感知-规划-执行-记忆”闭环，能够自主调用工具（Tool Calling）完成复杂任务，其核心在于提示词工程与函数调用机制。

## 四、问题与解决方案

| 问题 | 解决方案 |
| --- | --- |
| 文件上传后临时文件被自动删除 | 在 Controller 中立即调用 `transferTo` 持久化到本地或云存储 |
| JWT 解析时密钥不一致导致校验失败 | 统一在配置类中定义常量密钥，避免硬编码分散 |
| `@Transactional` 注解在非 public 方法或同类方法内部调用时失效 | 确保事务方法为 public，且通过代理对象调用（或将操作移至不同类） |
| AOP 切入点表达式匹配范围过大，误拦截非目标方法 | 改用 `@annotation` 方式，精准匹配自定义注解标记的方法 |
| 多个过滤器/切面执行顺序混乱 | 使用 `@Order` 注解明确指定优先级数值 |

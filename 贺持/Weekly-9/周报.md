&#x09;#web开发-HTML\&CSS

1、HTML：

HTML（HyperText Markup Language）：超文本标记语言。

超文本：超越了文本的限制，比普通文本更强大。除了文字信息，还可以定义图片、音频、视频等内容。

标记语言：由标签构成的语言  

HTML 标签都是预定义好的。例如：使用<a>展示超链接，使用<img>展示图片，<video>展示视频。  

HTML 代码直接在浏览器中运行，HTML 标签由浏览器解析。



2、CSS：

CSS（Cascading Style Sheet）：层叠样式表，用于控制页面的样式（表现）。

&#x09;一、HTTP协议

&#x09;	1、概念：HyperText Transfer Protocol，超文本传输协议，规定了浏览器和服务器之间数据传输的规则。



&#x09;	2、特点：

&#x09;		基于 TCP 协议：面向连接，安全

&#x09;		基于请求响应模型的：一次请求对应一次响应

&#x09;		HTTP 协议是无状态的协议：对于事务处理没有记忆能力。每次请求响应都是独立的。

&#x09;		缺点：多次请求间不能共享数据。

&#x09;		优点：速度快



&#x09;	3、请求数据格式

&#x09;		请求行：请求数据第一行 （请求方式、资源路径、协议）

&#x09;		请求头：第二行开始，格式 key: value

&#x09;		请求体：POST 请求，存放请求参数



&#x09;	请求方式\*\*



&#x09;		\*\*GET\*\*：

&#x09;		 	- 请求参数在请求行中，没有请求体。

&#x20; 				- 示例：`/brand/findAll?name=OPPO\&status=1`

&#x20; 				- GET请求大小是有限制的。



&#x09;		\*\*POST\*\*：

&#x20;				 - 请求参数在请求体中。

&#x20; 				- POST请求大小是没有限制的。



&#x09;	4、响应格式

&#x09;		响应行：响应数据第一行(协议、状态码、描述)

&#x09;		响应头：第二行开始，格式key: value

&#x09;		响应体：最后一部分，存放响应数据

&#x09;		

&#x09;		常见响应：

&#x09;		200 客户端请求成功。

&#x09;		404 请求资源不存在，一般是 URL 输入有误，或者网站资源被删除了。

&#x09;		500 服务器发生不可预期的错误。



&#x09;	5、HTTP协议解析

&#x09;		概念：HyperText Transfer Protocol，超文本传输协议，规定了浏览器和服务器之间数据传输的规则。

&#x09;#请求响应-请求

一、请求-简单参数\&实体参数

&#x09;1、原始方式：在原始的web程序中，获取请求参数，需要通过HttpServletRequest对象手动获取



&#x09;2、SpringBoot方式

&#x09;简单参数：

&#x09;参数名与形参变量名相同，定义形参即可接收参数

&#x09;如果方法形参名称与请求参数名称不匹配，可以使用@RequestParam完成映射

&#x09;3、@RequestParam注解

&#x09;方法形参名称与请求参数名称不匹配，通过该注解完成映射

&#x09;该注解的required属性默认是true，代表请求参数必须传递



&#x09;实体对象参数规则：请求参数名与形参对象属性名相同，即可直接通过POJO接收

&#x09;简单实体对象：请求参数名与形参对象属性名相同，定义POJO即可



&#x09;复杂实体对象：请求参数名与形参对象属性名相同，按照对象层次结构关系即可接收嵌套POJO属性参数



二、请求-数组集合参数

&#x09;1、数组参数：请求参数名与形参数组名称相同且请求参数为多个，定义数组类型形参即可接收参数

&#x09;2、集合参数：请求参数名与形参集合名称相同且请求参数为多个，@RequestParam绑定参数关系



三、请求-日期参数\&Json参数

&#x09;1、日期参数：使用@DateTimeFormat注解完成日期参数格式转换

&#x09;2、Json参数：JSON数据键名与形参对象属性名相同，定义POJO类型形参即可接收参数，需要使用@RequestBody标识



四、请求-路径参数

&#x09;1、路径参数：通过请求URL直接传递参数，使用{...}来标识该路径参数，需要使用@PathVariable获取路径参数

&#x09;如：

&#x09;@RequestMapping(“/path/{id}”)--->http://localhost:8080/path/123

&#x09;@RequestMapping(“/path/{id}/{name}”)--->http://localhost:8080/path/123/Tom



五、总结：

\### 简单参数

\- 定义方法形参，请求参数名与形参变量名一致。

\- 如果不一致，通过@RequestParam手动映射。



\### 实体参数

\- 请求参数名，与实体对象的属性名一致，会自动接收封装



\### 数组集合参数

\- 数组：请求参数名与数组名一致，直接封装

\- 集合：请求参数名与集合名一致，@RequestParam绑定关系



\### 日期参数

\- @DateTimeFormat



\### JSON参数

\- @RequestBody



\### 路径参数

\- @PathVariable

&#x09;#请求响应-响应

一、@ResponseBody

类型：方法注解、类注解

位置：Controller方法上/类上

作用：将方法返回值直接响应，如果返回值类型是 实体对象/集合，将会转换为JSON格式响应

说明：@RestController = @Controller + @ResponseBody ;



二、用处

&#x09;1、把返回值不做页面跳转，直接输出到 HTTP 响应体

&#x09;	不加这个注解时，Controller 方法返回字符串默认代表视图名称，SpringMVC 会去找页面文件做跳转（视图解析）。

&#x09;	加上@ResponseBody后，返回内容不再当作视图名，直接写给浏览器 / 前端。

&#x09;2、对象、集合自动转为 JSON

&#x09;	返回实体类对象、List 集合时，Spring 会调用 JSON 序列化工具，自动把 Java 对象转成 JSON 字符串返回给前端，前后端分离接口必备。

&#x09;3、可以加在类上，该类所有方法全部生效

&#x09;	写在 Controller 类上，类里面每一个接口方法都拥有@ResponseBody效果。

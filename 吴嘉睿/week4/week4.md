## 一、本周学习概述

本周开始围绕 AIC 多模态查询目标定位任务开展实践，重点从任务理解、数据组织、模型部署和推理链路验证四个方面入手。该任务要求模型根据文本查询，在 RGB、红外、深度等多模态图像中定位目标，并输出符合评测要求的归一化 bbox。相比普通图文问答，本任务更强调空间关系理解、重复目标消歧、输出格式稳定性和大模型部署效率。

本周主要完成了 Qwen3-VL 系列模型的本地与远程部署调研，梳理了数据集、预测文件、提交文件之间的字段约束，并针对显存、下载、缓存和远程主机环境做了多轮验证，为后续统一推理工作流打基础。

## 二、核心学习内容

### 2.1 AIC 多模态目标定位任务理解

本任务的核心输入包括图像组和自然语言查询，输出为每条查询对应的目标框。实际难点集中在以下方面：

| 难点 | 表现 | 应对思路 |
| ---- | ---- | -------- |
| 多目标重复 | 同类物体在同一图中多次出现 | 在 prompt 中强调位置、顺序、关系和可见性线索 |
| 多模态对齐 | RGB、红外、深度信息互补 | 保持统一像素坐标系，避免各模态单独推理后坐标漂移 |
| 输出格式严格 | 评测只接受固定字段和合法 bbox | 增加提交校验与 bbox 后处理 |
| 模型资源占用大 | 32B/38B 模型需要高显存或量化 | 区分本地烟测和远程全量推理配置 |

通过分析数据特征，确认同一 image_id 下可能对应多条 query，因此后续工作流需要支持按图像分组、复用图像编码结果，并保证每条 query 的输出仍然独立。

---

### 2.2 Qwen3-VL 模型部署与显存策略

本周先在本地 RTX 5080 Laptop GPU 上验证 Qwen3-VL-8B-Instruct 的可运行性。直接使用 BF16 与 `device_map=auto` 时，模型部分模块会占满显存并在生成阶段 OOM。经过测试，确定两条可行路径：

1. **4-bit NF4 量化**：适合本地快速 smoke test，显存占用更低，能够完成单图推理。
2. **BF16 + CPU offload**：在需要更高精度时使用，通过限制 GPU `max_memory` 将部分模块放到 CPU。

远程主机方面，选择在 RTX 6000D 环境使用 `Qwen/Qwen3-VL-32B-Instruct-FP8`。FP8 权重体积约 33GB，在 84GB 显存环境中更适合完整推理，同时质量预期优于 4-bit 量化。

---

### 2.3 模型下载、缓存与远程环境

大模型权重下载是本周的主要工程问题之一。针对远程主机网络和磁盘限制，完成以下处理：

- 将模型、HF cache、uv cache、数据集和输出统一放在 `/root/autodl-tmp`，避免系统盘空间不足。
- 使用分片 Range 下载方式，并保留 `.tmp` 断点文件，减少中断后的重复下载。
- 在低配无 GPU 模式下，将下载并发从高并发配置收敛到 64 个全局 worker，降低 2GB 内存限制下的 OOM 风险。
- 下载完成后清理 Range part、uv cache、aria2 控制文件和 Conda package cache，保留模型、数据集、代码和输出。

这些操作使远程环境能够在成本较低的状态下完成模型准备，并为 GPU 模式下的 smoke/full run 预留足够磁盘空间。

---

### 2.4 输出字段与提交校验

目标定位任务对提交格式要求严格，因此本周将提交文件约束提前纳入设计：

- 每条预测必须保留源 query 的原始字段。
- 每条预测只新增归一化 `bbox: [x1, y1, x2, y2]`。
- bbox 需要满足坐标顺序合法、范围合法、数值类型可序列化。
- 推理 raw 输出与最终提交输出分离，便于审计和调试。

在后续代码结构中，提交校验会作为推理工作流的固定步骤，避免模型输出格式不稳定导致最终评测失败。

## 四、问题与解决方案

### 4.1 本地显存不足导致 BF16 推理失败

**问题**：本地 GPU 即使空闲，BF16 自动 offload 仍可能把过多模块放入显存，生成阶段移动大模块时发生 OOM。

**解决**：将本地 smoke test 默认切换为 4-bit NF4；需要 BF16 时显式配置 CPU offload 和 `max_memory`，牺牲部分速度换取可运行性。

### 4.2 大模型下载容易中断

**问题**：FP8 权重体积大，网络中断后如果重新下载会浪费大量时间。

**解决**：使用 Range 分片下载并保留 `.tmp` 断点状态；在资源受限模式下降低并发，确保进程稳定完成。

### 4.3 提交格式容易被模型输出污染

**问题**：模型可能输出解释文本、非 JSON 内容或坐标越界，直接提交会失败。

**解决**：将 raw 输出和最终 submission 分离；统一由后处理模块解析 bbox、归一化坐标并运行提交校验。

## 六、总结与思考

本周的核心收获是认识到多模态定位任务不能只关注模型调用本身，工程链路同样决定最终结果是否可用。模型部署、显存策略、数据组织、输出校验和断点恢复都需要提前设计，否则全量推理时很容易因为一次格式错误或资源波动导致结果不可复现。

下一阶段的重点将从环境准备转向代码工程化：把临时验证脚本收敛为统一、可读、可恢复的工作流，并让不同模型只在 backend 层体现差异，其他流程保持一致。

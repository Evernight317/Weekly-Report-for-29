# 学习周报：Agent 系统测试验收与阶段性收尾

**周期**：2026年7月20日 - 2026年7月25日
**主题**：核心链路验证、检索效果评估、安全检查、部署文档与项目交接

## 一、本周学习概述

本周承接前两周已完成的 MCP 服务、RAG 知识库、LangGraph 编排引擎和 Web 端功能，不再继续扩展新的大型模块，而是将重点转向系统验收与阶段性收尾。主要工作包括：梳理 Agent 从用户提问到工具调用和答案返回的完整链路，补充关键场景测试；对 RAG 检索效果进行小规模评估；检查鉴权、日志脱敏和接口限流等基础安全项；整理部署步骤、配置说明和已知问题。通过本周工作，现有系统具备了较清晰的运行边界和交接条件，也为后续暂停该方向、转入其他学习内容做好准备。

## 二、核心学习内容

### 2.1 核心链路测试与验收

#### 2.1.1 测试范围收敛

由于本阶段目标是验证已有成果，而不是继续增加功能，本周将测试范围集中在四条关键链路：

| 测试链路 | 验证内容 | 验收标准 |
| -------- | -------- | -------- |
| 文档入库 | 上传、解析、分块、向量化 | 文档状态正确，失败时有明确提示 |
| 知识问答 | 问题分析、RAG 检索、答案生成 | 回答与来源一致，可查看引用片段 |
| 工具调用 | LangGraph 调度、MCP 调用、结果回传 | 调用过程可追踪，异常能够结束并返回提示 |
| 用户访问 | 登录鉴权、角色权限、数据隔离 | 未授权请求被拒绝，不同用户数据互不可见 |

测试策略以端到端冒烟测试为主，并针对检索、鉴权和错误处理补充少量接口测试。这样可以覆盖系统的主要风险，同时避免在项目即将收尾时引入过重的测试建设成本。

#### 2.1.2 典型场景验证

本周选取以下场景进行回归验证：

1. 上传一份 PDF 文档，确认解析完成后能够在检索测试页命中相关片段
2. 连续提出普通问题、知识库问题和无相关资料的问题，观察 Agent 是否正确选择工具
3. 模拟 MCP 服务暂时不可用，确认后端不会无限等待，并能向前端返回可理解的错误信息
4. 使用不同权限账户访问知识库管理接口，确认 RBAC 规则和用户数据隔离有效
5. 重启 Docker Compose 服务，确认数据库、向量索引和会话数据能够正常恢复

### 2.2 RAG 检索效果的小规模评估

#### 2.2.1 评估数据准备

从已有知识库文档中人工整理 30 个问题，覆盖事实查询、跨段落信息整合和无答案问题三类场景，并为每个问题标注预期命中的文档与片段。该数据集规模不大，但能够快速发现分块、召回和回答引用中的明显问题。

#### 2.2.2 评估指标

本阶段不搭建复杂的 LLM-as-Judge 平台，仅保留便于复现的基础指标：

| 指标 | 含义 | 本阶段用途 |
| ---- | ---- | ---------- |
| Hit@5 | 正确片段是否出现在前 5 条结果中 | 判断基础召回能力 |
| MRR | 正确片段在结果列表中的平均排名 | 判断结果排序质量 |
| 引用正确率 | 回答引用是否来自实际检索结果 | 检查答案可追溯性 |
| 无答案识别率 | 无相关资料时是否避免编造答案 | 检查系统边界意识 |

测试结果表明，普通事实类问题的召回表现较稳定；跨段落问题仍会受到文档分块边界影响。考虑到本阶段即将结束，本周只调整了少量分块参数和 Top-K 配置，没有继续引入新的检索框架或评估平台。

### 2.3 稳定性与安全检查

#### 2.3.1 超时与错误处理

对 Agent 调用链中的超时配置进行统一检查，重点覆盖 LLM 请求、MCP 工具调用、向量检索和 SSE 连接。对于可恢复错误保留一次重试，连续失败后立即终止当前任务，并在日志中记录请求 ID、失败节点和错误类型，避免 Agent 长时间停留在执行状态。

#### 2.3.2 基础安全项

本周完成以下基础检查：

- 为登录和对话接口设置简单的请求频率限制，降低接口被重复调用的风险
- 检查数据库查询参数，确认用户输入通过参数化方式传递
- 对日志中的 Authorization、API Key 和用户上传文件路径进行脱敏
- 检查 Docker Compose 环境变量，敏感配置仅从 `.env` 读取，不写入镜像和仓库
- 限制知识库允许上传的文件类型和大小，异常文件在解析失败后及时清理

这些措施主要用于补齐最基础的安全边界，尚未替代正式的渗透测试和生产级安全审计。

## 四、问题与解决方案

### 4.1 无相关资料时仍可能生成推测性回答

**问题**：当检索结果相似度较低时，模型仍可能根据通用知识补充回答，导致用户难以区分知识库内容与模型推测。

**解决**：增加最低相似度判断；低于阈值时明确提示“当前知识库中未找到足够依据”，并保留检索关键词供用户调整后重试。

### 4.2 工具调用失败后的状态不一致

**问题**：MCP 服务超时后，后端任务已经失败，但前端仍显示“执行中”。

**解决**：统一任务终态，失败时由后端发送包含错误类型的结束事件，前端收到后停止加载状态并提供重试入口。

### 4.3 部署配置分散

**问题**：模型地址、服务端口和密钥配置分散在多个文件中，重新部署时容易遗漏。

**解决**：整理 `.env.example` 和环境变量说明表，将必填项、默认值及用途集中记录，并在启动文档中加入部署前检查清单。

## 六、总结与思考

经过三周学习，项目已完成从协议与原型验证、系统整合，到测试验收和文档归档的基本过程。第一周重点打通知识库、MCP 与 Web 架构，第二周完成 LangGraph 编排、前后端功能和容器化部署，本周则主动控制范围，对核心链路进行了回归验证，并补齐了稳定性、安全边界和交接文档。

本阶段最大的收获不仅是掌握了 MCP、RAG 和 Agent 编排等技术，更重要的是认识到项目收尾同样需要明确边界。继续增加工具并行、复杂评估平台或完整生产部署，会显著扩大工作量，但对当前学习成果的完整性提升有限。因此，本周选择先确保现有系统可运行、可验证、可说明和可恢复，再将未完成事项清晰归档。至此，该 Agent 网站学习项目可以阶段性结束，为后续开展其他学习内容留出时间。

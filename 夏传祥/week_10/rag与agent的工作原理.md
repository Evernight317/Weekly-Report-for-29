# RAG 与 Agent 的工作原理

> **报告周期**：2026.09.07 - 2026.09.13

## 一、RAG

RAG 全称检索增强生成，核心思想是先检索、后生成，回答问题之前先从知识库里找出相关的内容，再把找到的内容连同问题一起交给大模型，让它基于这些材料来组织答案。这么做能解决大模型的三个痛点，一是训练数据有截止日期，新发生的事情它不知道；二是它没见过我们的私有数据；三是没有依据时它会编造内容，也就是幻觉，而检索到的真实材料正好能约束它。

整个流程分三个阶段。第一阶段是索引构建，把文档加载进来做清洗和预处理，然后切成一个个小块，一般按段落或固定长度切、块与块之间留一点重叠，避免语义被切断；再用 Embedding 模型把每个文本块转成向量，存进向量数据库里，常见的有 FAISS、Chroma、Milvus 这几种。第二阶段是检索，用户提问时把问题也转成向量，到向量库里算相似度，通常用余弦相似度，把最相关的前 K 个文本块取出来。第三阶段是生成，把检索到的文本块拼进提示词里，调用大模型生成回答，答案的依据就是刚才检索到的知识，所以幻觉会少很多，还可以在提示词里要求它标注出处。

RAG 相当于给大模型外挂了一个可随时查询的知识库，模型本身不用重新训练，知识更新了只需要更新库里的文档。

## 二、Agent 的 ReAct 框架

ReAct 的核心是让大模型按"思考 → 行动 → 观察"的循环来解决问题，三步分别对应 Thought、Action、Observation。Thought 是模型分析当前该做什么，Action 是调用一个外部工具，Observation 是拿到工具返回的结果，然后带着这个结果进入下一轮思考，如此循环，直到信息足够了输出最终答案。

它和一次性工具调用的区别在于轮次，普通做法是模型决定调哪个工具、调完直接生成回答，整个过程只有一次；ReAct 是多轮的，每一步都先看上一步的实际结果再决定下一步做什么，所以能处理需要连续推理的复杂任务，中间发现方向不对还能调整。

实现上靠提示词约束模型的输出格式，在提示词里告诉它有哪些工具可用、每个工具是干什么的，并要求它严格按 Thought / Action / Action Input 的格式输出；程序解析出工具名和参数后执行真正的调用，把返回值以 Observation 的形式拼回对话里再交给模型，循环往复，直到模型输出 Final Answer 为止。

和其他几种工作模式对比着看会更清楚，思维链 CoT 只在模型内部一步步推理，不与外界交互；Plan-and-Execute 是先制定一份完整计划再逐步执行，计划定了就不太变；Self-Ask 是模型自己提出子问题再逐个回答。ReAct 的特点是把推理和行动交替进行，每一步都用真实的观察结果来校正下一步的思考，这也是它更适合做 Agent 的原因。

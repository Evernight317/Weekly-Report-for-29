## 二、核心学习内容

### 2.1 MySQL 数据查询（DQL）

DQL（Data Query Language）是 SQL 中最核心的部分，用于从数据库中检索数据。完整语法结构如下：

```sql
SELECT 字段列表
FROM 表名
WHERE 条件
GROUP BY 分组字段
HAVING 分组后条件
ORDER BY 排序字段
LIMIT 分页参数
```

- **基本查询**：`SELECT 字段1, 字段2 FROM 表名`，可使用 `AS` 起别名，`DISTINCT` 去重。

- **条件查询（WHERE）**：掌握了比较运算符（`>`、`>=`、`<`、`<=`、`=`、`<>`）、逻辑运算符（`AND`、`OR`、`NOT`）、模糊查询（`LIKE`，`%` 匹配任意字符、`_` 匹配单个字符）、范围查询（`BETWEEN...AND...`、`IN(...)`）、空值判断（`IS NULL`、`IS NOT NULL`）。

- **聚合函数**：`COUNT`（计数）、`SUM`（求和）、`AVG`（平均值）、`MAX`（最大值）、`MIN`（最小值），注意聚合函数会忽略 NULL 值，COUNT(*) 不会。

- **分组查询（GROUP BY）**：通常与聚合函数配合使用，`WHERE` 在分组前过滤，`HAVING` 在分组后过滤。执行顺序：WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT。

- **排序查询（ORDER BY）**：`ASC` 升序（默认），`DESC` 降序，支持多字段排序。

- **分页查询（LIMIT）**：`LIMIT 起始索引, 每页条数`，起始索引 = (页码 - 1) × 每页条数，用于后端分页提高查询效率。

### 2.2 MySQL 多表设计

- **一对多关系**：在"多"的一方添加外键列，通过 `CONSTRAINT 外键名 FOREIGN KEY (本表列) REFERENCES 主表(主表列)` 建立外键约束，保证数据完整性。物理外键在实际项目中较少使用，更多在逻辑层面维护。

- **一对一关系**：在任意一方添加外键并设为 UNIQUE，或直接合并为一张表，常见于单表字段过多的拆分场景。

- **多对多关系**：引入中间表，中间表持有两方主键作为外键，联合组成主键。

- **案例实践**：设计了部门表（dept）与员工表（emp），dept 与 emp 为一对多关系，并通过建表 SQL 和初始数据完成搭建。

### 2.3 MySQL 多表查询

- **连接查询**：
    - **内连接（INNER JOIN）**：只返回两表匹配的行，`SELECT ... FROM A INNER JOIN B ON A.id = B.xxx_id`。
    - **外连接**：左外连接（LEFT JOIN）保留左表全部数据，右外连接（RIGHT JOIN）保留右表全部数据，不匹配的填充 NULL。

- **子查询**：
    - **标量子查询**：子查询返回单个值（一行一列），通常与 `=`、`>` 等配合。
    - **列子查询**：返回一列多行，配合 `IN`、`NOT IN`。
    - **行子查询**：返回一行多列。
    - **表子查询**：返回多行多列，通常放在 FROM 后作为临时表。

- **综合案例**：完成多表查询综合练习，能将业务问题转化为多表联查 + 条件过滤 + 排序分页的组合 SQL。

### 2.4 MySQL 事务与索引

- **事务**：
    - 事务是一组不可分割的操作集合，要么全部成功，要么全部失败回滚。
    - 操作：`START TRANSACTION` / `BEGIN` → 执行 SQL → `COMMIT`（提交）/ `ROLLBACK`（回滚）。
    - ACID 四大特性：原子性（Atomicity）、一致性（Consistency）、隔离性（Isolation）、持久性（Durability）。

- **索引**：
    - 索引是帮助 MySQL 高效获取数据的数据结构，默认使用 B+Tree。
    - 语法：`CREATE INDEX 索引名 ON 表名(字段名)`，查看索引 `SHOW INDEX FROM 表名`，删除索引 `DROP INDEX 索引名 ON 表名`。
    - 索引可大幅提升查询效率，但会降低增删改的速度并占用额外空间，需在常用查询条件和 WHERE/JOIN 字段上合理创建。

### 2.5 MyBatis 框架

- **MyBatis 概述**：一款优秀的持久层框架，用于简化 JDBC 开发。将 Java 对象与数据库记录自动映射，通过注解或 XML 配置 SQL。

- **快速入门**：
    - 引入 mybatis 和 mysql 驱动依赖
    - 配置数据库连接四要素（URL、用户名、密码、驱动类名）
    - 创建 Mapper 接口 + `@Mapper` 注解，方法上加 `@Select` / `@Insert` 等注解编写 SQL
    - 通过 `@Autowired` 注入 Mapper 调用方法

- **JDBC 回顾与对比**：JDBC 存在硬编码、操作繁琐、资源手动释放等问题，MyBatis 通过连接池（HikariCP）自动管理连接、预编译 SQL 防注入、自动映射结果集，开发效率大幅提升。

- **Lombok**：通过注解自动生成 getter/setter、构造方法、toString 等方法。常用注解：`@Data`（全能）、`@NoArgsConstructor`、`@AllArgsConstructor`、`@Slf4j`。

### 2.6 MyBatis 基础操作与动态 SQL

- **基础 CRUD**：
    - 删除：`@Delete("DELETE FROM emp WHERE id = #{id}")`，`#{}` 为预编译占位符，防止 SQL 注入。
    - 新增：`@Insert("INSERT INTO emp(...) VALUES(#{...}, ...)")`，使用 `@Options(useGeneratedKeys = true, keyProperty = "id")` 获取自增主键返回。
    - 更新：`@Update("UPDATE emp SET name=#{name} WHERE id=#{id}")`。
    - 查询：`@Select("SELECT * FROM emp WHERE id = #{id}")`，如果数据库字段名与实体属性名不一致，需开启驼峰命名映射或使用 `@Results` 手动映射。
    - 条件查询：使用 `CONCAT('%', #{name}, '%')` 实现模糊匹配。

- **XML 映射文件**：当 SQL 较复杂（如多条件动态查询）时，在 XML 文件中编写 SQL，通过 `namespace` 绑定 Mapper 接口，`id` 对应方法名，`resultType` 指定返回值类型。

- **动态 SQL**：
    - `<if test="条件">`：根据条件动态拼接 SQL，用于多条件组合查询。
    - `<foreach collection="ids" item="id" open="(" separator="," close=")">`：遍历集合生成 `IN (?, ?, ?)` 类语句，用于批量删除。
    - `<sql id="...">` + `<include refid="...">`：提取公共 SQL 片段复用。

### 2.8 登录认证与会话跟踪

- **基础登录**：前端提交用户名密码 → 后端查询数据库验证 → 登录成功返回结果。问题在于 HTTP 是无状态协议，无法记住登录状态。

- **会话跟踪方案演进**：
    - **Cookie + Session**：客户端存 Cookie（Session ID），服务端存 Session 对象。缺点：依赖 Cookie、跨服共享困难、服务器端存储压力。
    - **JWT 令牌（最终采用方案）**：登录成功后服务端生成加密令牌返回给客户端，客户端每次请求携带令牌（Header: `token: xxx`），服务端校验令牌合法性。优点：无状态、不占服务器内存、适合分布式。

- **JWT 实操**：
    - 引入 `jjwt` 依赖，使用 `Jwts.builder()` 生成令牌（设置载荷 + 签名密钥 + 过期时间），`Jwts.parser()` 解析校验令牌。
    - 登录接口验证成功后下发 JWT，前端存储到 localStorage，后续请求在请求头中携带。

- **Filter（过滤器）**：
    - 实现 `javax.servlet.Filter` 接口，重写 `doFilter()` 方法，在请求到达 Controller 前拦截。
    - 通过 `@WebFilter(urlPatterns = "/*")` 注册，`@ServletComponentScan` 启用扫描。
    - 登录校验过滤器逻辑：排除 `/login` 路径 → 从请求头获取 token → 解析 JWT → 校验通过则放行，失败则返回未授权。
    - 过滤器链：多个 Filter 按类名字母顺序依次执行，`filterChain.doFilter()` 将请求传给下一个过滤器。

- **Interceptor（拦截器）**：
    - 实现 `HandlerInterceptor` 接口，`preHandle()` 在 Controller 前执行，返回 true 放行 / false 拦截。
    - 通过 `WebMvcConfigurer` 的 `addInterceptors()` 注册，可精确指定拦截/放行路径。
    - 与 Filter 相比，Interceptor 是 Spring 框架提供的机制，能访问 Spring 上下文（可注入 Bean），更适合与业务逻辑集成。

- **Filter vs Interceptor**：Filter 是 Java Web（Servlet）级别，先于 Interceptor 执行，作用于所有请求；Interceptor 是 Spring MVC 级别，作用于 Controller 请求，能获取到 Handler 信息。

### 2.9 全局异常处理

- 使用 `@RestControllerAdvice` + `@ExceptionHandler` 定义全局异常处理器。
- 对不同异常类型（如 `SQLIntegrityConstraintViolationException`、`Exception`）分别处理，返回统一错误格式的 Result，避免异常信息直接暴露给前端。

## 四、问题与解决方案

| 问题 | 解决方案 |
|------|----------|
| SQL 查询结果中字段值为 NULL 时聚合函数统计异常 | 使用 `IFNULL(字段, 默认值)` 函数将 NULL 替换为指定值再参与计算 |
| 多表联查出现笛卡尔积（结果条数暴涨） | 检查是否遗漏了连接条件（ON 子句），确保每张表之间都有明确的关联条件 |
| MyBatis `@Select` 查询后实体属性为 NULL，数据库字段名与 Java 属性名不一致（如 `dept_id` vs `deptId`） | 在 `application.properties` 中开启 `mybatis.configuration.map-underscore-to-camel-case=true` 驼峰映射 |
| PageHelper 分页不生效 | 检查 `PageHelper.startPage()` 是否紧挨着查询方法调用（中间不能有其它操作），以及依赖版本是否支持当前 SpringBoot 版本 |
| 文件上传大小超过限制报错 | 在 `application.yml` 中配置 `spring.servlet.multipart.max-file-size=10MB` 和 `max-request-size=100MB` |
| 阿里云 OSS 上传时 AccessKey 硬编码在代码中不安全 | 将 AccessKey 等配置抽取到 `application.yml`，使用 `@ConfigurationProperties` 自动绑定，避免硬编码，且便于环境切换 |
| Filter 中校验 JWT 时无法注入 Spring Bean（如 Service） | Filter 是 Servlet 组件，不受 Spring 管理。改用 Interceptor（`HandlerInterceptor`），可以在 `preHandle` 中正常使用 `@Autowired` 注入的 Bean |
| JWT 解析失败后没有统一错误格式 | 在全局异常处理器中添加对 `JwtException` 及认证相关异常的捕获，统一返回 `{code: 0, msg: "NOT_LOGIN"}` |

## 六、总结与思考

本周完成了从"数据库操作"到"完整 Web 应用开发"的跃迁，是四周以来收获最大的一周。几点核心体会：

- **从单表到多表是 SQL 的分水岭**：单表查询相对直观，但多表联查涉及 JOIN 类型选择、子查询位置、字段去重等一系列问题，需要先在脑中建模"我要查什么、数据来自哪几张表、表之间如何关联"，再动手写 SQL，否则很容易写出笛卡尔积或漏掉数据。

- **MyBatis 真正解决了 JDBC 的痛点**：在学习了 JDBC 的原始写法后再使用 MyBatis，对比非常明显——预编译 SQL 自动防注入、自动结果映射省去 while 循环赋值、连接池自动管理避免资源泄漏。每个特性都能对应到 JDBC 的一个痛点。

- **案例驱动是最高效的整合方式**：通过 Tlias 项目把一个完整后台管理系统的 CRUD 流程走通之后，SpringBoot 的三层架构不再只是概念，而是实际写代码时的本能分层。尤其是"前端发请求 → Controller 接收 → Service 处理 → Mapper 查库 → 封装 Result 返回"这条链路已经很清晰了。

- **认证和授权是 Web 安全的基石**：Cookie/Session/JWT 的三代演进非常经典，理解之后又学了 Filter 和 Interceptor 两层拦截机制，补上了"如何处理每个请求"这一环。JWT 是无状态的，适合当前的分布式微服务趋势。

- **始终保持"先原理再操作"**：学习 JWT、Filter、AOP 等内容时，每次先花时间搞清楚"这个技术解决了什么问题"，理解设计意图，再动手写代码，效率远高于直接看 API 照着敲。这个习惯要一直保持。

四周下来，从 Java SE 基础逐步过渡到能独立完成一个后台管理系统的 CRUD + 文件上传 + 登录认证的完整流程，整体进度和效果都符合预期。

## 二、核心学习内容

### 2.1 Java 基础

- **深浅拷贝与序列化**：
    - 浅拷贝：只复制对象本身，引用类型的成员仍指向原对象（`clone()` 默认行为，`BeanUtils.copyProperties` 也是浅拷贝——项目里 DTO 拷贝要注意成员是 List/对象时会被共享）。
    - 深拷贝：对象及其整棵引用对象图全部新建。**序列化/反序列化实现深拷贝**的原理：序列化把整个对象图写入字节流，反序列化按流中的数据重新创建每一个对象，因此副本与原对象完全独立；要求类实现 `Serializable`，static/transient 字段不参与，且反序列化绕过构造方法。
- **同步 / 异步、阻塞 / 非阻塞**：
    - 同步异步看"调用方等不等结果"：同步必须等被调方返回，异步立即返回、结果稍后通过回调/轮询/事件/消息获取。
    - 阻塞非阻塞看"等待结果的过程中线程是否被挂起"。
    - 异步的实现手段：多线程/线程池、消息队列、Future/CompletableFuture、事件驱动。
- **NIO 同步非阻塞（延伸）**：
    - 核心三大件：Channel、Buffer、Selector。`configureBlocking(false)` 后，`read()` 没有数据立即返回 0 而不是阻塞线程。
    - 单线程 + Selector 的"多路复用"：线程只阻塞在 `selector.select()` 上，由内核（Linux epoll）通知"哪些连接就绪"，就绪后线程自己完成读写——所以是**同步**（读写由应用线程完成）**非阻塞**（不会傻等单条连接）。
    - 与 Redis 单线程模型呼应：Redis 也是"单线程 + IO 多路复用"，原理同源。

### 2.2 Java 集合

- **集合体系总览**：Collection / Map 两大体系，List 有序可重复、Set 去重、Queue 排队、Map 键值对；结合项目选型——购物车"同品查重"用 Map O(1) 优于 List 遍历 O(n)，订单明细/购物车列表用 List（有序可重复），分类去重用 HashSet。
- **ArrayList 源码**：
    - 底层 `Object[]`；`new ArrayList()` 指向共享空数组 `DEFAULTCAPACITY_EMPTY_ELEMENTDATA`，**首次 add 才扩容到 10**。
    - 扩容机制：`size + 1 > 容量` 时 `grow`，`newCapacity = oldCapacity + (oldCapacity >> 1)` 即 **1.5 倍**，`Arrays.copyOf`（底层 `System.arraycopy`）搬数据；有容量预判时用 `new ArrayList<>(n)` / `ensureCapacity` 避免多次扩容。
    - 复杂度：尾部 add 均摊 O(1)、头尾/中间插入删除 O(n)、随机访问 O(1)；`RandomAccess` 标记接口影响 `Collections.binarySearch` 的二分策略。
    - fail-fast：迭代器持有 `expectedModCount`，遍历中结构性修改抛 `ConcurrentModificationException`；安全删除用 `Iterator.remove()` / `removeIf()`。
    - subList 返回的是**视图**，对原列表增删后再访问会抛异常，要独立副本需 `new ArrayList<>(subList)`。
- **HashMap 源码**：
    - 底层：数组 + 链表 + 红黑树（JDK8）；put 流程：hash 扰动 → `(n-1)&hash` 定位 → 空桶直接放 / 覆盖 / 尾插 → 链表 ≥8 且数组 ≥64 树化 → size 超 threshold 扩容。
    - 扩容：2 倍扩容，元素按 `hash & oldCap` 决定留原位或移到"原索引 + 旧容量"，无需重新计算位置；负载因子 0.75、`threshold = 容量 × 负载因子`。
    - 2 的幂设计：`(n-1)&hash` 等价取模且更快；`tableSizeFor` 把指定容量向上取整成 2 的幂（如 100 → 128）。
    - 线程不安全：并发 put 覆盖、JDK1.7 头插法扩容可能形成环形链表死循环（JDK8 尾插法解决但仍有覆盖）、`size++` 非原子。
    - 扰动函数 `h ^ (h >>> 16)` 让高位参与散列；null 键 hash 为 0 存 table[0]。
- **Set 与排序**：HashSet 基于 HashMap，去重依赖 hashCode + equals（必须一起重写）；LinkedHashSet 保持插入顺序、TreeSet 红黑树自动排序；Comparable（类内固有排序）vs Comparator（外部定制排序，`thenComparing` 支持多级排序，对应销量 Top10 的降序 + 次级排序场景）。
- **并发容器**：ConcurrentHashMap 与 Hashtable 对比；**JDK1.7 分段锁（Segment 继承 ReentrantLock，默认 16 段）→ JDK1.8 Node + CAS + synchronized（只锁桶首节点、读不加锁）**；为什么 key/value 不能为 null（并发下 get 返回 null 有二义性）；"先查后写"复合操作不原子，要用 `putIfAbsent` / `compute` / `merge` 等原子 API。

### 2.3 Java 多线程

- **基础概念**：进程是资源分配基本单位、线程是 CPU 调度基本单位（线程共享堆和方法区，私有程序计数器、虚拟机栈、本地方法栈）；并发（单核交替）vs 并行（多核同时）；上下文切换开销；线程创建 4 种方式（Thread / Runnable / Callable+Future / 线程池）；线程 6 种状态（NEW → RUNNABLE ↔ BLOCKED/WAITING/TIMED_WAITING → TERMINATED）；`start()` 才是启动新线程，直接调 `run()` 只是普通方法调用。
- **线程协作**：死锁四条件（互斥、占有并等待、不可剥夺、循环等待）与预防（固定加锁顺序、tryLock 超时、jstack 排查）；`sleep`（Thread 静态方法、不释放锁）vs `wait`（Object 方法、释放锁、必须在同步块）；**wait/notify 为什么定义在 Object**——它们操作的是对象的 monitor 和等待集合，锁挂在对象上而非线程上，定义在 Thread 会语义错乱；必须配合 synchronized 是为了避免"丢失唤醒"。
- **JMM（Java 内存模型）**：
    - 主内存与工作内存：所有变量存主内存，线程在自己的工作内存（缓存副本）中读写，这就是**可见性**问题的根源。
    - 并发三特性：原子性、可见性、有序性。
    - happens-before 规则（程序次序、volatile 变量规则、锁规则、传递性等）：保证"先写入后读"的顺序语义。
    - 重排序（编译器/指令级/内存系统）与 as-if-serial；volatile 通过**内存屏障**禁止重排。
- **volatile**：保证可见性 + 有序性，**不保证原子性**（`count++` 读-改-写三步不安全）；适合"状态标志"场景（如项目里缓存开关）；双重检查锁（DCL）单例必须加 volatile 防止"先赋引用后初始化"的重排。
- **synchronized 与锁**：三种用法（实例方法锁 this、静态方法锁 Class 对象、代码块锁指定对象）；底层 monitor（monitorenter/monitorexit）、可重入；与 ReentrantLock 对比（可中断、超时、公平锁、多个 Condition）。
- **原子类与 CAS**：`AtomicInteger` 通过 CAS（比较并交换，底层 Unsafe）保证原子性；CAS 的 ABA 问题（用版本号 `AtomicStampedReference`）；高竞争时自旋反而低效。
- **异步概念**：异步 = 不等结果立即返回；实现方式与代价（事务边界、ThreadLocal 上下文丢失、异常定位难）；`CompletableFuture` 编排。

## 四、问题与解决方案

| 问题 | 解决方案 |
|------|----------|
| 误以为 Spring Task 的任务队列是 LinkedBlockingQueue | 查阅源码确认：Spring Task 底层是 `ScheduledThreadPoolExecutor`，任务队列是 `DelayedWorkQueue`（基于最小堆的延迟队列）；LinkedBlockingQueue 是普通线程池的默认队列 |
| ArrayList"初始容量 10"表述不严谨 | `new ArrayList()` 实际指向空数组 `DEFAULTCAPACITY_EMPTY_ELEMENTDATA`，首次 add 才扩容到 10；答题时表述为"首次添加时初始化为 10" |
| 深拷贝 / 浅拷贝概念混淆（以为 BeanUtils 是深拷贝） | 明确 `BeanUtils.copyProperties` / `clone()` 是浅拷贝；深拷贝用序列化/反序列化：整个对象图重建，要求实现 Serializable，static/transient 不参与、绕过构造器 |
| 同步阻塞与异步非阻塞概念绕晕 | 用两个维度拆开：同步异步看"等不等结果"，阻塞非阻塞看"等待时线程是否挂起"；NIO 是"同步 + 非阻塞"（内核只通知就绪、读写由线程完成），AIO 才是真正异步 |
| wait/notify 为什么定义在 Object 讲不清 | 它们操作的是对象的 monitor 和等待集合，锁挂在对象上；定义在 Thread 无法回答"线程持有多把锁时释放哪把"，语义错乱 |
| HashMap 树化阈值 8 的来源数值记不住 | 答"泊松分布下链表长度到 8 的概率极低"即可，不背具体小数，避免答错扣分 |
| 多线程并发修改集合出现 ConcurrentModificationException | 遍历删除用 `Iterator.remove()` / `removeIf()`；批量删除交给 MyBatis `<foreach>` 生成 IN 语句，从源头避免遍历中修改集合 |
| 误以为 ConcurrentHashMap 能保证"先查后写"复合操作原子性 | 用 `putIfAbsent` / `computeIfAbsent` / `merge` 等原子 API；购物车同品累加可用 `map.merge(dishId, 1, Integer::sum)` |

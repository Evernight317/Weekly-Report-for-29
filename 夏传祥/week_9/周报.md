## 二、核心学习内容

### 2.1 苍穹外卖面试题库的整理

以提问方的视角把项目相关的考点分成了十二个模块，合计二十六道以上的题目，每道都标注了考察点和答题要点。一是开场必答的部分，包括项目介绍该怎么讲、Maven 聚合工程是怎么拆模块的、一个请求从 Nginx 到数据库中间经过了哪些层；二是登录认证，员工端和用户端的流程差别、JWT 与 Session 的取舍、拦截器校验的完整链路，以及 ThreadLocal 在 BaseContext 里的存取和清理；三是 AOP 公共字段自动填充的实现思路和全局异常处理的组织方式；四是 Redis 这一块，项目里到底哪些地方用到了缓存、数据变了之后缓存怎么保证一致、穿透击穿雪崩这三个问题在实际业务里怎么防；五是购物车和下单，防止重复添加的做法、下单的完整流程、订单明细为什么要存快照、事务边界划在哪里、超时订单怎么定时处理；六是支付和实时通信，微信支付的异步回调链路、WebSocket 来单提醒的连接管理；七是数据库和 MyBatis，十一张表之间的关系、动态 SQL 的标签、#{} 和 ${} 的区别、PageHelper 的分页原理；余下还有几道开放场景题，高并发下单怎么优化、Redis 挂了怎么降级、防超卖有哪些做法。

答题上总结出了一个通用的框架，就是先说背景和需求，再讲方案，接着是难点和坑，然后是权衡，收尾落在反思上，每个知识点都按两到三层的深度把追问准备好，这样被往下挖的时候不至于断在半路。

### 2.2 模拟面试的演练与纠偏

前后做了两轮完整的模拟，从项目介绍开始一层层往下挖，走到架构分层、DTO/VO/Entity 的区分、登录认证链路、JWT 为什么伪造不了、和 Session 的对比、ThreadLocal 的脏数据问题、AOP 自动填充、通知类型怎么选，一直问到缓存一致性。

这轮演练的价值不在于答对了多少，而在于把一批自以为已经掌握、实际上一开口就露馅的点全找了出来，具体的错误都记在了第四节的问题表里，就其中影响最大的几处而言，AOP 通知类型的选型、JWT 的结构、Entity 的定义、缓存一致性的推理过程，这几项放到真实面试里都是要扣分的。同时也练出了两条应对方式，一是没把握的时候把不确定讲明白、再给出自己的推理方向，比硬猜一个答案要好得多；二是被要求举例的时候必须落到具体的表和具体的业务场景上，只给结论等于没答。

### 2.3 Java 向 Agent 开发转型的调研

把 2026 年 Java 这边的 AI Agent 技术栈查了一遍，在 Maven Central 上核实到 Spring AI 已经到 2.0.1、LangChain4j 到了 1.20.0，工具调用、RAG、MCP、Agent 编排这些能力在 Java 生态里都已经补齐，转型这件事不需要换语言，现有的 SpringBoot 工程能力有九成能直接接着用。

在这个基础上定了一个六阶段、十到十二周的安排，先是 LLM 的基础概念，用 HttpClient 裸调一次 Chat API 建立感觉；然后进 Spring AI，把 ChatClient、Advisor、结构化输出这些核心 API 用起来；接着做 RAG 知识库；再往后是工具调用和 Agent 模式，重点理解 ReAct 的循环；之后是 MCP 和工程化；往后是长期的跟进。路径上采取的做法是把新能力长在苍穹外卖这个项目上，先做运营知识库的 RAG，再把现有的 Service 方法包一层 @Tool 做成 AI 点餐 Agent，末了把接口封装成 MCP Server，这样每一步都能复用已有的积累，不用从零另起一套。计划已经整理成文档存进了学习计划文件夹，后面附了打卡表。

### 2.4 MySQL 与 SQL 的现状评估

MySQL 的进阶内容分成了两档来看。一档是面试级的，包括索引为什么用 B+Tree、最左前缀、事务的隔离级别、MVCC 的基本原理、三大日志的作用，还有 explain 怎么看执行计划，这一档是现在就要过的，两三天能走完，前面课程里 DQL、多表、事务、索引都学过一遍，现在要做的是把理解往上提一层。另一档是架构级的，主从复制、分库分表、锁的深水区这些，属于社招和真实大规模业务才会碰到的东西，苍穹外卖是单体项目、数据量也小，这一档往后放，等明年找实习前配合真实场景再学。

SQL 这边结合项目的真实表结构出了八道手写题做自测，从基础的排序分页，到分组后过滤、子查询的三种写法、多表聚合算销量 Top10、按天统计营业额、去重查询，难度是递进的，同时把几个经典坑整理了出来，一是 WHERE、GROUP BY、HAVING、SELECT、ORDER BY、LIMIT 的执行顺序，二是 COUNT(*)、COUNT(列)、COUNT(DISTINCT 列) 三者的差别，三是 LEFT JOIN 的过滤条件写在 ON 和写在 WHERE 结果完全不同，四是 NULL 只能用 IS NULL 判断。结论是语法基础并不缺课，缺的是手写时的流畅度，需要靠自测来验证。

## 四、问题与解决方案

| 问题 | 解决方案 |
|------|----------|
| 模拟中答成"@Before 拿不到方法参数，自动填充必须用 @Around" | 核实后纠正过来，所有类型的通知都能通过 JoinPoint 拿到方法签名和参数，课程官方的实现恰恰就是 @Before 加反射赋值，靠的是引用传递，方法执行前把字段改好就行；@Around 只在需要控制方法是否执行、修改返回值、统计耗时这几种场景下才不可替代 |
| 把 ThreadLocal 说成了"存到 Thread 里" | 术语上纠正，ThreadLocal 是线程私有的存储空间，项目里由 BaseContext 做了封装；afterCompletion 里调 remove 不光是防内存泄漏，更重要的是防线程池复用线程时读到上一个请求残留的脏数据 |
| 以为 JWT 的载荷里放了签名密钥 | 概念上纠正，JWT 分 Header、Payload、Signature 三段，密钥只存在服务端，签名是拿密钥对前两段算出来的结果，改了 payload 就必须重算签名，所以伪造不出来；Payload 是 base64 明文，谁都能解，不能往里放敏感信息 |
| Entity 的定义答错了，说成"程序里传输数据的类" | 纠正为与数据库表一一对应的映射类，是 MyBatis 做 ORM 的载体；DTO 管前端能传什么，VO 管前端能看到什么，Entity 管数据库里有什么，三者分开的核心考虑是安全，避免前端伪造金额、状态这类字段 |
| 缓存一致性只答出了"先更库再删缓存"这个结论，理由讲不通 | 把并发的时序推演补上了，先删缓存再更库的话，读请求会在中间那个空档把旧值回填进去，造成很长时间的不一致；还准备了两个追问的应对，一是为什么删缓存而不是改缓存，二是删除失败之后靠延迟双删、消息队列重试和 TTL 兜底 |
| 被问到"A 的 id 串到了 B 的请求里"时硬猜是 token 解析出错 | 正确的归因是线程池复用加上 ThreadLocal 没清理导致的脏数据；也从中吸取了教训，没把握的时候把不确定讲出来、给出推理方向，比硬猜一个答案要好 |
| 觉得这一周什么都没学，产生了焦虑 | 认知上做了调整，这一周属于巩固和输出的性质，模拟面试把模糊的知识变成了确定的理解，Agent 计划把第二成长曲线定了下来，输出和规划本身就是学习的一部分 |

## 六、总结与思考

这一周表面上看没学多少新东西，实际起到的作用比预想的要大。

一是输出这件事本身就是最好的检验，模拟面试让好几个自以为已经懂的点当场翻车，AOP 的通知选型、JWT 的结构、缓存一致性的推理都在其中，会用和能讲清楚之间的差距，只有真的开口讲一遍才能暴露出来，这也正是八股复习试点的意义所在，目的不是多背几道题，而是把模糊的确定变成确定的明白。

二是错误是这一周里最值钱的部分，演练中暴露出来的每一个认知偏差，放到真实面试里都是实打实的丢分点，在模拟里发现并且当场纠正，代价要比在面试现场发现小得多，这些错误都进了问题表，下次复习优先重看。

三是方向比速度更重要，Agent 转型的计划给出了 Java 后端之外的第二条成长曲线，"在已有项目上长出新能力"这条路径让每一步都能复用已有的积累，不至于从零开始另起炉灶。

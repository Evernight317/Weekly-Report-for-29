# 学习进度总结

> **提交人**：夏传祥
> **统计截至**：2026.11.14

## 一、Pydantic 与数据契约

- **模型与字段**：读完官方文档的 Models 和 Fields 两页之后，把项目里要用的数据结构落成了代码，`Field` 的默认值怎么给、`default_factory` 和可变类型是什么关系、`extra="forbid"` 怎么把未知字段挡住，这几处都自己过了一遍。
- **当前产物**：五个模型加一个 DAG 容器已经成型，状态机把九种状态的合法转移写死了、非法转移直接抛异常，配套的验证脚本盯住默认值、字段校验、序列化、状态机和未知字段，现在是全绿的状态。

## 二、LangChain

- **模型接入**：OpenAI 兼容协议底下还是三件套，API Key、模型名和 base_url，`init_chat_model` 这个统一入口和各家的客户端都用过，`model_provider` 什么时候必须显式传也弄清楚了。
- **提示词**：`PromptTemplate` 和 `ChatPromptTemplate` 两种模板都会用，`partial_variables` 能把一部分变量先填掉，`MessagesPlaceholder` 用来把历史消息插进去，模板之间还可以拼接、也能从 JSON 或 YAML 里读出来。
- **结构化输出**：三档递进，先在提示词里把格式讲清楚，再用 `get_format_instructions` 把格式说明回灌给模型，最后拿 `PydanticOutputParser` 或 `with_structured_output` 由模型定义兜住底线。
- **LCEL**：`prompt | model | parser` 是最基本的写法，并行、分支和普通函数节点怎么接进链里也跑通过。
- **会话记忆**：`RunnableWithMessageHistory` 按 `session_id` 挂历史，内存和 Redis 两种存储可以换着用。
- **工具调用**：`@tool` 装饰器把普通函数变成工具，docstring 直接当描述，`args_schema` 交给 Pydantic 约束参数，`bind_tools` 之后再把参数解析出来交给函数，一个调用闭环就齐了。
- **RAG**：六种文档加载器都试过，递归切分里 `chunk_overlap` 会让各段长度之和比原文长出一截、重叠被算了两次，向量库写入和相似度检索也走过一遍，检索链能自己拼。

## 三、LangGraph

- **状态与规约器**：默认行为是覆盖，`Annotated` 配上 `operator.add` 才是追加，`add_messages` 专给消息列表用；`operator.mul` 上有个恒等元的坑，初值 0.0 会让结果一直是 0。
- **流程控制**：普通边管无条件跳转，`add_conditional_edges` 按路由函数的返回值选分支，路由挂在 `START` 上就成了条件入口。
- **动态结构**：`Command` 把状态更新和跳转目标合并返回，`Send` 用来做 map-reduce 式的动态并行。
- **持久化**：检查点以 `thread_id` 为键，既能取到当前状态和历史序列，也能改掉某个历史点再重跑。
- **子图**：直接拿子图当节点会合并两次状态，父子状态不一致的时候得用代理节点手动转换。
- **多智能体**：handoff 靠工具移交，`create_supervisor` 由主管统一调度，这两种的共同点是拓扑固定。

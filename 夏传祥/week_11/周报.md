## 二、核心学习内容

### 2.1 Python 基础

有 Java 的底子，语法层面过得很快，精力主要花在两种语言的差异上。一是动态类型，变量不用声明类型，赋值即创建，写起来灵活但也少了编译期的类型检查，习惯了 Java 的强类型之后要适应"错误留到运行时才暴露"这一点；二是缩进即语法，没有大括号，代码块靠缩进划分，强制了代码风格统一；三是常用的数据结构，list、tuple、dict、set 和 Java 的 ArrayList、数组、HashMap、HashSet 基本能一一对应上，dict 的推导式和切片操作是 Python 特有的简洁写法。

除此之外还过了函数定义与默认参数、*args 和 **kwargs 可变参数、模块导入机制、文件读写和 with 上下文管理，以及面向对象部分——Python 的类没有 private 关键字，靠命名约定区分，继承和方法重写比 Java 轻量很多。练习时写了一些基础的小脚本，把语法点都过了一遍手，为后面调用平台 API 和写 Agent 脚本做准备。

### 2.2 RAG 与个人知识库搭建（课件第 1 章）

RAG 的概念之前在学长的任务里已经理过一遍，这次跟着课件又系统走了一次，重点补上了"为什么需要"和"执行流程"两块的细节。RAG 全称检索增强生成，核心是先检索后生成，回答之前先从知识库里找出相关内容，再把内容连同问题一起交给大模型组织答案，解决的正是大模型的三个痛点——训练数据有截止日期、没见过私有数据、没有依据时会幻觉。

流程上按三段记：索引阶段把文档加载、清洗、切块，再用 Embedding 模型转成向量存进向量库；检索阶段把问题也转成向量，按相似度取回最相关的文本块；生成阶段把文本块拼进提示词交给模型，让它基于材料回答。这周还实际动手用 **Cherry-Studio** 和 **ima** 两个零代码工具搭了自己的个人知识库，把平时积累的学习资料灌进去，直接对着知识库提问验证效果，从"知道概念"到"用过工具"这一步算是走完了，两个平台的搭建流程、知识库配置和问答效果也做了对比。

### 2.3 Coze 与 Dify 智能体开发（课件第 2 章）

这一章先把智能体的概念框架立了起来。AI Agent 的发展阶段、核心要素（大模型做决策中枢、工具做执行手段、记忆做上下文、规划做任务拆解）、应用领域过了一遍，最有用的是"搭建智能体的三个 level"这个分级：Level 1 是预设提示词创建简易智能体，本质上就是精心设计的系统提示词，Cherry-Studio 里就能建；Level 2 是用工作流，把多个步骤按固定顺序编排起来，适合流程确定的任务；Level 3 是用 Coze 这类平台搭高阶智能体，模型自己决定调用哪个工具、走哪条分支，适合开放性任务。

平台方面认识了国内最主流的两个低代码 Agent 平台——**Coze（扣子，字节出品）**和 **Dify（开源，可私有化部署）**，两者的定位差异也理清楚了：Coze 上手快、插件生态全、适合快速验证想法；Dify 开源可私有部署、工作流编排更精细、更贴近企业生产环境。这个 Level 分级对自己很有参照价值，之前在苍穹外卖上设想的 AI 点餐助手就属于 Level 3 的形态。

### 2.4 入门案例实操（课件第 3 章）

跟着课件做了五个内容生成类的工作流案例，每个都在 Coze 和 Dify 双平台上对照实现：**一键生成行业调研 PPT**（搜索资料、提炼要点、生成大纲再转 PPT）、**复刻爆款视频**（拆解视频结构、生成对应脚本）、**产品营销海报生成**（提取卖点、生成文案与配图）、**一键生成行业调研报告**、**客户投诉分类助手**（分类结果对接钉钉推送）。

五个案例做下来，对工作流的节点编排有了肌肉记忆——开始节点收参数、大模型节点做生成、插件节点调外部能力、选择器做分支、结束节点出结果，Dify 里还能把工作流发布成 API。案例本身偏内容生成，难度不高，但把"提示词怎么写节点才稳定输出""变量怎么在节点之间传递"这些工程细节都摸了一遍，这正是后面做数据分析类复杂案例的基础。

## 四、问题与解决方案

| 问题 | 解决方案 |
|------|----------|
| Python 缩进报错频发，IndentationError 反复出现 | 从 Java 的大括号习惯切过来不适应，把编辑器缩进统一设成 4 空格、关闭 Tab 混用，写代码时刻意注意块级结构，几天后形成习惯 |
| 动态类型下变量类型错误到运行时才暴露 | 关键函数加类型注解（type hints）提高可读性，复杂逻辑先在 REPL 里小步验证，再往脚本里搬 |
| Cherry-Studio 知识库问答效果不稳定，有时检索不到相关内容 | 排查发现是文档切块过大导致检索粒度太粗，调整分块大小、把长文档按主题拆小后重新向量化，召回明显改善 |
| Coze 工作流里大模型节点输出格式不稳定，下游节点解析失败 | 在提示词里明确要求输出格式并给示例（Few-shot），必要时在选择器节点前加格式校验分支，重试机制兜底 |
| Dify 客户投诉分类案例对接钉钉时推送失败 | 检查钉钉机器人的 Webhook 地址和安全设置（关键词/加签），确认工作流里请求节点的 Header 与 Body 格式符合钉钉 API 要求后调通 |
| 两个平台同样的工作流效果有差异，不确定以哪个为准 | 理解到差异来自默认模型和节点实现的不同，同一案例在两边各跑一遍做对照，把平台特性记下来，选型时按场景决定——快速验证用 Coze，要精细控制和私有化用 Dify |

## 六、总结与思考

这一周是 Agent 方向的正式起步，几点体会：

- **低代码和写代码是两条互补的路，不是二选一**。之前定的 Spring AI 计划是代码优先，直接对着原理写；这周走的平台路线是先把效果做出来，五个工作流案例跑完之后，对"Agent 到底在干什么"有了直观体感——大模型做决策、工具做执行、工作流做编排，这些概念在平台上拖一遍比看十篇文章都清楚。接下来用代码实现时，心里是有画面的。

- **三个 Level 的分级给了自己清晰的定位**。Level 1 的提示词智能体、Level 2 的固定工作流、Level 3 的自主决策智能体，复杂度和适用场景逐级上升。回头看自己在苍穹外卖上设想的 AI 点餐助手，属于 Level 3 的形态，需要模型自主决定调哪个 Service，这也印证了转型计划里"把 Agent 长在已有项目上"的路线是对的——项目里现成的接口就是 Level 3 智能体的工具集。

- **RAG 从概念到落地只差一个动手**。之前对 RAG 的理解停留在流程图上，这周用 Cherry-Studio 把自己的学习资料灌进去、真的对着它提问之后，切块大小对检索效果的影响、召回不准时该调什么，这些问题都有了切身答案。工具搭建暴露出来的问题，恰恰是原理层面最该弄懂的地方。

- **Python 补课比预想的顺利**。有 Java 的底子，语法几天就能上手，真正要适应的是动态类型的思维方式。按计划 Python 是读懂 LangChain 生态的钥匙而不是主战场，现在的程度已经够用了，后面结合 API 调用多写脚本保持手感即可。。

## 📝 核心知识点梳理

### 1. HTTP 协议与接口设计（RESTful 规范）
*   **请求（Request）与响应（Response）**：后端的核心工作就是“接收 Request，处理逻辑，返回 Response”。
*   **常用 HTTP 方法与语义**：
    *   `GET`：从服务器获取资源（无 Request Body）。
    *   `POST`：向服务器新建资源。
    *   `PUT / PATCH`：更新服务器上的资源。
    *   `DELETE`：删除服务器上的资源。
*   **常见 HTTP 状态码**：
    *   `200 OK`：请求成功。
    *   `201 Created`：资源创建成功。
    *   `400 Bad Request`：前端传递参数有误。
    *   `404 Not Found`：路由或资源不存在。
    *   `500 Internal Server Error`：后端代码崩溃或数据库报错。

### 2. 核心代码实践：Express/Web 服务示例
编写了一个基础的 RESTful 接口服务：

```javascript
const express = require('express');
const app = express();

// 1. 中间件：解析 JSON 格式的请求体
app.use(express.json());

// 模拟数据库数据
let users = [
    { id: 1, name: '张三', role: 'admin' }
];

// 2. GET 接口：获取用户列表
app.get('/api/users', (req, res) => {
    res.status(200).json({ success: true, data: users });
});

// 3. POST 接口：新增用户
app.post('/api/users', (req, res) => {
    const { name, role } = req.body;
    if (!name) {
        return res.status(400).json({ success: false, message: '用户名不能为空' });
    }
    const newUser = { id: users.length + 1, name, role: role || 'user' };
    users.push(newUser);
    res.status(201).json({ success: true, data: newUser });
});

// 启动服务器监听 3000 端口
app.listen(3000, () => {
    console.log('后端服务已启动：http://localhost:3000');
});
```

### 3. 数据库交互与持久化
*   理解了**内存数据（临时）**与**数据库持久化（永久）**的区别。
*   掌握了在后端代码中创建数据库连接池（Connection Pool），避免频繁建立/关闭连接造成的性能损耗。
*   **SQL 参数化查询**：在执行查询时使用占位符（如 `?` 或 `$1`），防止 **SQL 注入** 安全漏洞。

## ❓ 遇到的问题与解决方案

1.  **问题：前端或 Postman 提交 POST 请求时，后端 `req.body` 为 `undefined`**  
    *   *原因*：没有加载解析请求体的中间件。
    *   *解决*：在路由定义前添加 `app.use(express.json())`（或对应语言的 Body Parser）。

2.  **问题：跨域问题（CORS Error）**  
    *   *原因*：浏览器同源策略限制，前端（如 8080 端口）调用后端（3000 端口）时被拦截。
    *   *解决*：引入并配置 `cors` 中间件，允许指定来源的请求访问。

## 一、 Agent 的工作原理与理解方式

### 1. ReAct 框架深度解析

如果说传统 LLM 只是“问一句答一句”的静态工具，那么 ReAct（Reason + Act）就是让 AI 拥有了“大脑思考 + 动手做事”的动态闭环。

- **核心循环流程**：
  1. **Thought（思考）**：分析当前状态，推理出“我现在知道什么”、“我还需要知道什么”以及“下一步该做什么”。
  2. **Act（行动）**：调用外部工具（如搜索引擎、数据库、API）去获取信息。
  3. **Observation（观察）**：获取工具返回的结果，并重新回到 Thought 阶段进行迭代，直到解决问题。

### 2. 其他常见 Agent 工作模式

- **模式 1：Chain of Thought (CoT) - 纯推理**：引导模型一步步写出思考过程，适合复杂的逻辑推导，但不涉及外部工具调用。
- **模式 2：Plan-and-Execute - 先计划后执行**：先让 Agent 宏观拆解任务步骤（Plan），然后再稳扎稳打地一步步执行（Execute），适合长周期、多步骤的复杂任务。
- **模式 3：Self-Ask - 自问自答**：通过自己提出子问题并逐个击破，来解决层层嵌套的复杂大问题。

## 二、 RAG

在实际业务中，大模型常常因为“没看过私有数据”而胡说八道。RAG 技术就像是给大模型外挂了一个“开卷考试的资料库”。

### 1. Indexing 索引构建

- **核心逻辑**：原始文档不能直接塞给 AI，必须经过“数据获取→ 文档预处理 →文档分块 (Chunking)→向量化 (Embedding) →存储到向量数据库”这一套标准流水线。

### 2. Retrieval 检索

- **核心逻辑**：当用户提问时，系统会先把问题转为向量，去向量数据库里比对，找出最相似的知识片段。

### 3. Generation 生成

- **核心逻辑**：把“用户的问题” + “检索出来的私有知识片段”一起打包塞进 Prompt 里，再交给 LLM 润色总结，从而输出言之有据的精准答案。

## 三、 RAG 进阶高级检索与优化策略

为了应对更复杂的查询场景，RAG 衍生出了多种高阶检索策略：

### 1. Multi-Query（多查询策略）

- **核心思想**：用户的单一提问可能带有主观局限性。通过让 LLM 从多个不同角度改写和扩展用户的查询语句，多路并发去检索，防止漏掉关键信息。

### 2. RAG-Fusion（多查询结果融合策略）

- **核心思想**：结合 **RRF（Reciprocal Rank Fusion，倒数排名融合）** 算法，把多路查询检索出来的结果集进行交叉比对、重新排序与去重，取长补短，大幅提升检索结果的含金量。

### 3. Decomposition（问题分解策略）

- **核心思想**：当面对一个复合型、高难度的大问题时，系统会先将其拆解为多个互相关联的小问题，逐个击破并汇总，适合深度逻辑分析场景。

### 4. Step-Back（问答回退策略）

- **核心思想**：当用户提问过于具体、细节化时，系统**先退一步**，把具体问题抽象成一个更高阶、更宏观的通用背景问题，先搞懂底层原理，再结合具体问题去检索。

### 5. HyDE（假设性文档嵌入）

- **核心思想**：用户的短查询（Query）和知识库的长文档（Document）在向量空间里往往“不对齐”。HyDE 的思路是：**先让大模型凭空“盲猜”写一篇假设性的标准答案（假文档）**，然后拿这篇假文档去向量数据库里搜真实文档。因为“文档和文档长得很像”，从而大幅提升检索的准确率。

## 学习周报

### 一、学习内容

**1. 登录校验 - JWT 令牌**

1）JWT 简介与生成 JWT（JSON Web Token）由 Header、Payload、Signature 三段组成，用 `.` 拼接。Header 存算法类型，Payload 存业务数据，Signature 用密钥对前两段签名，防止数据被篡改。引入 jjwt 依赖后生成令牌：

```java
// 生成令牌：登录成功后调用，返回给前端
String jwt = Jwts.builder()
        .subject("login")                          // 主题
        .claim("id", 1)                            // 自定义数据
        .claim("username", "张三")
        .issuedAt(new Date())                      // 签发时间
        .expiration(new Date(System.currentTimeMillis() + 12 * 3600 * 1000))  // 过期时间12小时
        .signWith(SignatureAlgorithm.HS256, "itheima")   // 签名算法 + 密钥
        .compact();
// 解析令牌：校验请求中的 token 是否合法
Claims claims = Jwts.parser()
        .setSigningKey("itheima")                  // 与生成时密钥保持一致
        .parseClaimsJws(jwt)
        .getBody();
Integer id = claims.get("id", Integer.class);
```

2）登录校验流程 登录成功 → 后端生成 JWT 返回给前端；前端后续请求在请求头 `Authorization` 中携带该令牌；后端统一拦截校验令牌，校验通过才放行访问受保护接口，令牌过期或非法则提示重新登录。

**2. Filter 过滤器**

1） Filter 可以对请求进行拦截过滤。实现 `Filter` 接口重写 `doFilter`，加 `@WebFilter` 指定拦截路径，启动类加 `@ServletComponentScan` 扫描：

```java
@WebFilter(urlPatterns = "/*")          // 拦截所有请求
public class LoginCheckFilter implements Filter {
    @Override
    public void doFilter(ServletRequest request, ServletResponse response, FilterChain chain)
            throws IOException, ServletException {
        // 放行前逻辑：校验 token
        chain.doFilter(request, response);   // 放行
        // 放行后逻辑
    }
}
```

2）执行流程 请求进入过滤器后，先执行放行前代码 → `chain.doFilter` 放行到目标资源 → 响应返回后再执行放行后代码。

3）登录校验过滤器 拦截所有请求，放行登录接口，其余请求从请求头取出 token 并解析校验，无效则返回提示信息：

```java
// 校验失败直接返回，不放行
response.setContentType("application/json;charset=utf-8");
response.getWriter().write("NOT_LOGIN");
```

**3. Interceptor 拦截器**

1）入门 拦截器是 SpringMVC 提供的，实现 `HandlerInterceptor` 接口，注册到 `WebMvcConfigurer` 中并配置拦截 / 放行路径：

```java
@Component
public class LoginCheckInterceptor implements HandlerInterceptor {
    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler)
            throws Exception {
        // 放行前执行，返回 true 放行，false 拦截
        return true;
    }
}
@Configuration
public class WebConfig implements WebMvcConfigurer {
    @Autowired
    private LoginCheckInterceptor loginCheckInterceptor;

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(loginCheckInterceptor)
                .addPathPatterns("/**")          // 拦截所有请求
                .excludePathPatterns("/login");  // 排除登录接口
    }
}
```

2）Filter 与 Interceptor 区别 Filter 属于 Servlet 规范，能拦截所有资源（含静态资源）；Interceptor 属于 SpringMVC，只拦截 Controller 请求，且在 Filter 之后执行。登录校验采用 "二选一" 即可，避免重复拦截。

### 二、遇到难题解决方法

**问题 1：** 生成的 JWT 解析时报错，令牌校验不通过。 **解决：** 确认生成与解析使用同一个密钥（`signWith` 和 `setSigningKey` 的密钥必须一致）；解析时用 try-catch 捕获异常，令牌过期或签名非法统一返回 "未登录" 提示，引导前端跳转重新登录。

**问题 2：** 配置拦截器后登录接口也被拦截，导致无法登录。 **解决：** 在注册拦截器时用 `excludePathPatterns("/login")` 放行登录请求；Filter 方案则在 `doFilter` 中先判断请求路径，登录接口直接 `chain.doFilter` 放行。
